# 投稿稿审稿风险响应矩阵

本文档服务 `docs/paper_notes/CNN_FPGA_GKP_submission_draft.tex` 的下一轮投稿化整理。它把 `审稿人视角_note成稿差距与材料清单.md` 中的主要审稿风险转写成 manuscript-facing response：哪些风险已经通过保守措辞或附录 guardrail 被压住，哪些仍必须靠新证据或后续材料补齐。

本文档不是 rebuttal letter，不是新实验，不改变 `T90` 当前唯一任务，也不升级任何 benchmark、`.tflite`、real-board、training reproducibility 或 `statcalib` 证据等级。

## 一句话判断

当前投稿稿的最佳策略不是把证据写强，而是把审稿人会质疑的边界写清：主结果只支撑 bounded software-HIL systems-method claim；硬件、expanded benchmark、机制因果、full reproducibility 和 statcalib promotion 均需要后续独立证据。

## 建议在稿件中的位置

1. 主文 Discussion：保留 1 段 limitations，不把风险矩阵全部塞进主文。
2. Appendix：保留 `Reviewer-Risk Response Matrix`，作为审稿前自查和作者 guardrail。
3. Supplement：未来 source-data bundle 成熟后，把 benchmark protocol、figure data、statcalib no-promotion 和 hardware placeholder 分开成独立 supplement tables。
4. Cover letter：不要提前写强 rebuttal，只强调稿件主动限定了 evidence boundary。
