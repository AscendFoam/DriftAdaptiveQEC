## 1. 一句话总评

当前投稿稿已经从“项目 note”推进为一篇有完整论文结构、source-data guardrail 和边界意识的 bounded software-HIL systems-method manuscript draft。它现在最强的可投稿命题不是“实现了 FPGA GKP decoder”，也不是“CNN 解码器达到 SOTA”，而是：

> 近似 GKP 物理层校正可以组织为一个 dual-loop affine calibration contract：慢环根据 syndrome statistics 更新低维校准面，快环只执行确定性的 \(\Delta = Ks+b\)，从而把 drift adaptation、可审计 fast path 和未来 hardware validation surface 分离出来。

这个命题是清楚的，也比早期 note 里的 CNN/FPGA 叙事更安全。但是从审稿人角度看，它仍不能被宣布为完整高质量投稿包。核心原因不是文字不够像论文，而是 strongest evidence 仍停在 software-HIL、proxy metric、descriptive ranking、一个场景的 formal interval 和 future hardware measurement surface。若目标是高质量期刊，仍需要一轮 evidence-hardening 和 manuscript compression。

## 3. 当前最强可支持主张

### 3.1 可以写入主文的主张

1. **架构主张**
   可以说稿件提出了 dual-loop affine calibration formulation：慢环估计或学习低维校准参数，快环执行确定性 affine correction。

2. **bounded software-HIL 主结果**
   可以说在当前 predeclared four-scenario software-HIL benchmark 中，hybrid residual calibration 在 reported `final_ler` mean 上低于 EKF、UKF、constant residual 和 RLS residual rows。

3. **paired descriptive advantage**
   可以说已有 paired deltas 方向一致，并给出描述性优势幅度；但必须保留 `n=2` 或 descriptive boundary，不能写成 significance。

4. **one-scenario formal interval**
   可以说 `static_bias_theta` 的 formal Phase A 12 paired repeats 已完成，UKF-minus-Hybrid delta 的 paired-t 95% interval 和 bootstrap 95% interval 下界为正。
   不能说全四场景完成 formal interval，也不能说 overall significance。

5. **metric ladder 主张**
   可以说稿件把 LER proxy、residual-boundary surrogate、fixed-point software parity、hardware measurement requirements 分开，从而降低了 metric conflation。

6. **hardware-facing formulation**
   可以说 fast path 的形式适合作为未来 FPGA/board validation target，因为 online state 和 arithmetic footprint 小、参数可 stage/commit、source-vs-board vectors 可定义。
   不能说已经 FPGA-validated。

### 3.2 只能放在 Supplement / Limitations 的主张

- controlled oracle-affine / wrapped-Gaussian / nearest-syndrome checks：只能作为 diagnostic sanity check，不是正式 competitor benchmark。
- holdout drift stress：只能作为 controlled non-hardware stress diagnostic，不是 trained-branch holdout generalization。
- commit-lag sweep：只能说明 stale-parameter sensitivity，不是 measured FPGA latency。
- statcalib：只能作为 supplementary statistical-calibration analysis supporting the calibration-contract story，不能晋升为 main comparator 或 mature promoted mode。
- source-data audit：只能证明表格/CSV/manifest 机械一致，不能证明 full reproducibility。

### 3.3 目前禁止写成结论的主张

- FPGA timing closure、resource efficiency、power、board latency、source-vs-board agreement。
- real-board execution success、closed-loop HIL success、deployment readiness。
- `.tflite` default runtime success 或 portable embedded runtime。
- full finite-energy GKP logical-channel fidelity、process fidelity、outer-code LER。
- statistically significant all-scenario advantage、p-value evidence、broad robustness。
- trained CNN branch unseen-drift holdout generalization。
- statcalib promotion 或 mature comparator closure。
- SOTA decoder、best GKP decoder、normalized leaderboard 胜出。

## 4. 实验可信度判断

### 4.1 已可信的部分

1. **表格与 source-data 机械一致性可信**
   `投稿稿source_data机械审计报告.md` 报告 `PASS_WITH_LIMITATIONS`，已检查主 benchmark 表、figure source CSV、controlled analysis CSV、manifest、coverage matrix、literature crosswalk、Phase A gate 和 formal interval row。它支持“当前稿件表格可追溯到本地 source data”这一层可信度。

2. **T24-style software-HIL descriptive ranking 可信**
   主 benchmark 的四场景五模式、paired seeds 和 repeated rows 有明确 CSV/JSON 回链。作为 bounded software-HIL descriptive anchor，它是可用的。

3. **static_bias_theta formal interval 可信**
   `submission_draft_phase_a_paired_interval_analysis.csv` 显示 `static_bias_theta` 已有 12 paired repeats，UKF-minus-Hybrid mean delta 为 `0.015563263889`，paired-t 95% interval 为 `[0.014778069884, 0.016348457894]`，bootstrap 95% interval 为 `[0.014934419560, 0.016268381944]`，`12/12` positive pairs。这个结果可支持单场景 interval-positive statement。

4. **fast-path cost / fixed-point parity 作为 feasibility evidence 可信**
   这类结果是 analytical/software-emulation 层级，可信但边界有限。

5. **external literature positioning 基本可信**
   `submission_draft_literature_metric_crosswalk.csv` 把外部文献数值、source anchor、number policy 和 non-claim boundary 分开，降低了误用外部硬件/decoder 指标的风险。

### 4.2 仍不够可信的部分

1. **统计强度不足**
   主 benchmark 仍主要来自少量 repeats；formal interval 只完成一个 scenario。审稿人会认为 all-scenario repeat-expanded evidence 缺失。

2. **generalization 不足**
   holdout drift stress 是 controlled diagnostic，不是 trained branch 在 unseen drift families 上的 formal benchmark。它不能证明 drift robustness。

3. **物理 fidelity 不足**
   residual-boundary surrogate 不等于 finite-energy logical-channel fidelity。若题名或摘要强调 fidelity，当前证据不够。

4. **硬件证据为空**
   目前没有 board log、bitstream/RTL hash、DMA/MMIO evidence、timing distribution、resource/power report、source-vs-board vector。任何 hardware result wording 都会被审稿人否掉。

5. **reproducibility 仍是 manuscript traceability，不是 external reproducibility pack**
   目前有 source-data manifest 和 audit，但没有完整环境锁定、跨主机复跑、recursive run hash closure、container/package manifest 或 archived data release。

6. **comparison fairness 仍需更强 formal comparator ladder**
   controlled nearest-syndrome/oracle/wrapped-Gaussian checks有价值，但还不能替代正式 baseline benchmark。审稿人会问：如果 full wrapped posterior 或 known-noise affine baseline formally run，会不会改变结论？

## 5. 三份审稿人报告

### Reviewer 1：技术严谨性与实验充分性

**总体意见**：稿件提出的 affine calibration contract 是合理且有用的，但当前实验还没有充分支撑广义 drift-adaptive GKP correction claim。作者正确地区分了 software-HIL、surrogate、fixed-point emulation 和 future hardware measurement，但这也暴露出强证据缺口。

**主要问题**：

1. Four-scenario benchmark 太窄，且 formal interval 只完成 `static_bias_theta`。
2. 主结果仍缺 all-scenario paired interval、effect size、predeclared stopping rule 和 pooled analysis。
3. Controlled baseline 不等于正式 competitor benchmark；wrapped-Gaussian / nearest-lattice 需要更接近主 protocol 的比较。
4. logical-channel surrogate 不能支撑 fidelity-level claim。
5. hardware language 应进一步降级，除非补 synthesis/timing/resource/power/source-vs-board evidence。
6. training reproducibility 和 artifact provenance 仍不足以让外部读者复现全部结果。

**建议**：

- 完成 Phase A 全四场景 12 paired repeats，最好扩展到 16 paired repeats，并给出 scenario-wise paired intervals。
- 对每个 scenario 做 missing-row accounting、seed list、config hash、runner version、commit hash。
- 增加 formal nearest-syndrome / known-noise affine / wrapped-Gaussian baseline ladder，至少在同一 protocol 下跑一组可审计子实验。
- 若继续保留 fidelity 小节，新增 finite-energy logical-channel simulation；否则把 fidelity 词汇全部限定为 surrogate readout。

**可能结论**：major revision before external submission。

### Reviewer 2：创新性与定位

**总体意见**：稿件最有新意的地方不是 CNN，也不是 FPGA，而是把 GKP physical-layer drift correction 重新表述为 low-dimensional runtime calibration surface。这个定位有价值，但稿件需要更主动地说明它相对 analog soft-information decoding、calibration-conditioned learned decoders 和 real-time FPGA decoders的差异。

**主要问题**：

1. Novelty story 仍偏防守：稿件花很多篇幅说明“不 claim 什么”，但需要更清楚说明“实际贡献是什么”。
2. 与 FiLM / AI pre-decoder / calibration-conditioned decoder 的差异需要在 Introduction 和 Discussion 里更直接。
3. 与 FPGA decoder 文献的关系应写成 validation standard，而不是隐含 competitor。
4. “low latency / low cost / noise adaptation” 三个优势目前是分层证据：low latency 是 analytical/path-complexity，low cost 是 operation/state footprint，noise adaptation 是 bounded software-HIL ranking + diagnostics。三者不能混成一个 hardware advantage。
5. 如果硬件仍是 future work，题名、摘要和 conclusion 应避免让读者预期真实 FPGA implementation。

**建议**：

- 把核心贡献重写成三条：
  1. GKP drift correction as affine runtime calibration contract。
  2. Software-HIL evidence that a teacher-anchored residual slow loop improves the protocol-defined proxy under four predeclared drifts。
  3. Validation ladder separating proxy LER, surrogate channel language, software arithmetic parity and future board measurements。
- Related Work 的 comparison tables 保留，但主文应更精炼：每类文献只回答“已解决什么 / 本文不 claim 什么 / 本文补什么”。
- 把 external hardware numbers 主要放在 evidence bar，而不是像 performance comparison。

**可能结论**：conceptually promising, but current evidence supports a bounded systems-method paper rather than a high-impact experimental claim。

## 8. 与相关工作的对比意见

### 8.1 GKP analog / soft-information decoding

稿件应承认：analog GKP syndrome information 和 soft-information decoding 已经是成熟方向，本文不是发明 analog information。本稿的差异应写成：

- 不尝试替代 surface-GKP / QLDPC-GKP outer decoder；
- 不 claim threshold / overhead；
- 聚焦 physical-layer drift adaptation 和 runtime-bounded affine correction surface。

### 8.2 Calibration-aware QEC

已有工作显示 calibration、prior adaptation、device drift 和 decoder prior 对 QEC 性能重要。本文应把自己的位置写成：

- 把 calibration 显式约束到 slow loop；
- 让 fast path 仍是 deterministic low-dimensional transform；
- 提供 source-data / validation ladder 使未来 hardware check 更容易。

不要写成本文首次提出 calibration-aware QEC。

### 8.3 Learned low-latency decoders

FiLM、AI pre-decoder、neural decoder 和 calibration-conditioned decoder 是强邻近工作。本文必须直接说明：

- 本文不是 per-shot neural decoder；
- CNN/residual module不在 latency-critical path 上；
- 本文主张 neural/statistical module 可作为 slow-loop surface updater；
- 当前没有真实量子处理器 experimental samples，不能与 Sycamore / hardware-data learned decoder 同指标对比。

### 8.4 Real-time FPGA decoders

LILLIPUT、Helios、Collision、qLDPC FPGA、Caune、Yang、Ziad、Maurer 等文献提供真实硬件 latency/resource/closed-loop 标准。本文应使用这些文献定义 evidence bar，而不是直接说本方法更快。

正确写法：

- “These works define the measurement standard for hardware claims.”
- “The present study only specifies the measurement surface.”

错误写法：

- “Our FPGA decoder is faster/lower-cost.”
- “The method is FPGA-validated.”
