# 投稿稿审稿意见驱动主文强化记录

**日期**：2026-07-03  
**对象**：`docs/paper_notes/CNN_FPGA_GKP_submission_draft.tex`

## 目的

本文记录一次审稿意见驱动的主文强化。修改目标是让投稿稿更像正式系统方法论文，而不是项目审计材料；同时不升级任何硬件、统计、`.tflite`、real-board 或 logical-channel 证据等级。

## 修改内容

1. 在 Introduction 中补入更明确的三点贡献界定：物理层 GKP affine calibration、slow-loop estimator 与 fast-path contract 分离、以及围绕同一 runtime surface 组织实验和验证。
2. 在 metric-readiness table 前加入 metric ladder 段落，区分 `final_ler` ranking、residual-boundary channel-language surrogate、analytical/software latency argument 和未来 FPGA timing。
3. 在 approximate GKP syndrome model 中明确 `eta_meas` 与 `eta_GKP` 只是当前软件模型中的 effective readout / finite-squeezing terms，不是 calibrated finite-energy device channel。
4. 修正 physics-model table 中 wrap interval 的半开区间写法：`[-lambda/2, lambda/2)`。
5. 在 controlled oracle / wrapped-Gaussian baseline 段落前加入审稿式定位：这些是 fast-path approximation sanity checks，不是 formal known-noise benchmark。
6. 在 Discussion 中补入正向 FPGA-facing systems claim：affine datapath 的优势是形成更小的 source-vs-board verification target，而不是已经有 measured hardware latency。
7. 将末尾 `Future Validation` 的枚举式任务队列改为 `Outlook`，按 statistical benchmark expansion、physics/channel validation、hardware validation 三条路线组织。

## 边界

- 不引用 2026-07-03 timed-out partial run。
- 不把 `final_ler` 写成 finite-energy logical-channel fidelity。
- 不把 analytical operation count 或 Q4.20 software parity 写成 FPGA timing/resource result。
- 不把 hardware placeholder 写成 real-board success。
- 不把 descriptive paired-bootstrap envelope 写成 confidence interval、standard error、p-value 或 significance test。
