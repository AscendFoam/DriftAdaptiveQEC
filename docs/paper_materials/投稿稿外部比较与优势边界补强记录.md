# 投稿稿外部比较与优势边界补强记录

日期：2026-07-03

本文档记录 `docs/paper_notes/CNN_FPGA_GKP_submission_draft.tex` 在“正式论文语体与比较指标改写”之后的追加补强。目标是让稿件更像面向外部审稿人的完整论文，同时不把当前软件 benchmark、硬件计划或 sidecar 尝试写成更强证据。

## 本轮补强内容

1. 在外部比较表中加入 “logical-error and overhead targets” 维度，用 surface-GKP 文献中常见的 failure-rate、threshold 和 mode/qubit overhead 结果作为读者参照。
2. 在外部比较表中加入 “logical-channel fidelity and infidelity” 维度，用 approximate-GKP logical channel、loss-channel infidelity 和 loss/amplification performance 文献作为 fidelity 类指标参照。
3. 明确本文主指标更窄：当前结果是 fast GKP correction layer 的 protocol-defined logical-error proxy，不是端到端 surface-GKP overhead、fault-tolerant threshold、真实硬件 logical error rate、logical-channel fidelity 或 process infidelity。
4. 在 Discussion 中把优势拆成三个层级：
   - latency：来自固定 affine fast path `Delta_t = K_t s_t + b_t`，其硬件意义是低状态、低分支、适合流水线的控制结构；
   - noise adaptation：来自 slow-loop calibration 选择 `K_t, b_t` 后交给 fast loop 执行，当前只由四个 scripted drift scenarios 和 paired descriptive deltas 支持；
   - cost：目前是硬件实现假设，只有在 fixed-point agreement、resource use、power 和 timing closure 完成后才能转成实测结论。
5. 进一步降低硬件表述强度：当前稿件只能说 physical support depends on future FPGA measurements，不能写成已经证明了硬件优势。

## 稿件可写边界

当前稿件可以写：

- 本方法在 scripted drift software benchmark 中相对 UKF baseline 显示出 descriptive improvement；
- paired deltas 只作为 `n=2` matched-seed descriptive comparison；
- affine fast path 给出 latency-oriented implementation rationale；
- hardware tables 和 figures 是 planned measurement slots；
- external comparison 用来定位任务层级，不把本文 claim 扩写到 surface-code overhead 或 fault-tolerance threshold。
- fidelity / infidelity 文献只用来说明当前稿件还缺少 channel-level evaluation，不把 `final_ler` 写成 fidelity。

当前稿件不能写：

- CI、p-value、statistical significance 或 broad robustness；
- true real-board execution success；
- fixed-point / `.tflite` / FPGA deployment closure；
- surface-GKP overhead reduction；
- logical-channel fidelity、process infidelity 或 logical-channel tomography；
- statcalib mature comparator promotion；
- sidecar repeat run 已经补齐统计证据。

## 后续材料需求

若要把当前投稿稿继续推近高质量期刊完整论文，最需要补三类材料：

1. 一个可完成的 paper benchmark expansion protocol：明确 scenario subset、repeat count、paired seeds、wall-time budget、resume policy、table schema 和 exclusion rule。
2. 一个硬件测量包：fixed-point agreement、latency/resource/power/timing closure、on-board I/O contract 和失败样本记录。
3. 一个统计说明包：预注册 metric、paired comparison plan、minimum repeat count、confidence interval 或 Bayesian interval 的适用条件，以及不满足时的保守措辞。
