# 投稿稿理论到配置桥接审计

**生成日期**：2026-07-02
**服务对象**：`docs/paper_notes/CNN_FPGA_GKP_submission_draft.tex`
**审计目的**：把投稿稿中的 GKP 漂移、自适应校准和 affine fast path 符号，与当前可验证的 T24 frozen software-HIL 配置、运行记录和代码入口对齐。

本文档不是新实验，不改变 `T24` frozen set，不升级任何 `.tflite`、real-board、statcalib 或 hardware 证据等级。它只回答一个审稿人会问的问题：稿件中的理论对象，当前到底由哪些配置字段和运行 artifact 支撑，哪些仍只是未验证的物理解释或后续工作。

## 1. 一句话结论

当前投稿稿可以把核心命题写成：

> Drift-adaptive GKP correction is instantiated as a dual-loop affine calibration contract: the fast path applies \(\Delta_t=K_t s_t+b_t\), while a slower loop updates \((K_t,b_t)\) from recent syndrome statistics under controlled synthetic drift scenarios.

这句话的可信边界是 `mock-backed software-HIL`。当前证据可以支持“受控合成漂移场景下的 affine calibration ranking”，不能支持完整物理噪声模型、真实硬件漂移、广义 GKP logical channel、deployment closure 或 paper-grade expanded benchmark。

## 3. 四个 T24 场景的理论到配置映射

T24 使用 `cnn_fpga/config/p4_multiscenario_strong_baselines.yaml`，继承 `p4_multiscenario_hybrid_b_long.yaml` 和 `p4_multiscenario.yaml`。运行记录位于 `runs/p4_benchmark/T24_formal_software_revalidation_20260510_200743/`，其中 `summary.json` 记录：

- `config_hash = b82874392710`
- `git_commit = 0c82ee1`
- `protocol_id = p4_strong_baselines_v1`
- `paired_seeds = true`
- `repeats = 2`
- four scenarios: `static_bias_theta`, `linear_ramp`, `step_sigma_theta`, `periodic_drift`
- five modes: `ekf`, `ukf`, `constant_residual_mu`, `rls_residual_b`, `hybrid_residual_b`

| Scenario | Config fields | Theory interpretation | Current support | Missing before stronger claim |
| --- | --- | --- | --- | --- |
| `static_bias_theta` | `type: static`, fixed `sigma0`, `mu_q0`, `mu_p0`, `theta_deg0` | fixed effective bias/orientation offset | Tests calibration under a stationary biased synthetic state | Does not prove physical device static miscalibration |
| `linear_ramp` | `type: linear`, `sigma_alpha`, bounded `sigma_min/max`, noisy `theta_deg0` around `theta_step_std_deg` | monotone scale drift plus orientation jitter | Tests adaptation lag under a simple synthetic ramp | Does not cover random-walk, burst/reset or mixed covariance holdout |
| `step_sigma_theta` | `type: step`, `jump_round`, `delta_sigma`, `delta_mu_q`, `delta_mu_p`, `delta_theta_deg` | abrupt variance/bias/orientation change | Tests response to a discontinuity in the effective state | Does not prove robustness to arbitrary jump timing or hardware events |
| `periodic_drift` | `type: periodic`, `sigma_amplitude/frequency`, `theta_amplitude_deg/frequency`, jitter | oscillatory drift in effective scale/orientation | Tests tracking under a smooth recurring perturbation | Does not establish broad sinusoidal or nonperiodic generalization |

推荐稿件用语：

- 可以写：`controlled synthetic drift scenarios instantiate perturbations of the effective affine calibration surface`.
- 可以写：`the four locked scenarios probe stationary, ramp, step and periodic adaptation demands`.
- 不要写：`the benchmark reproduces physical hardware drift`, `the noise model is complete`, `the result generalizes to all GKP drift processes`.

## 4. 代码层桥接锚点

当前可读代码给出的最小桥接链条是：

1. `cnn_fpga/config/p4_multiscenario.yaml` 定义四类 `mock_signal`。
2. `cnn_fpga/benchmark/run_hil_suite.py` 读取 `mock_signal.type`，并按 `static`、`linear`、`step`、`periodic` 生成 `sigma_value`、`mu_q_value`、`mu_p_value`、`theta_value`。
3. `cnn_fpga/benchmark/run_p4_multiscenario_benchmark.py` 按 scenario/mode/repeat 写出 per-repeat rows，并汇总为 T24 `comparison.csv` / `summary.json`。
4. 投稿稿图表和 source-data helper 目前只审计了主表、图件 source CSV、T24 CSV/JSON 和 figure manifest 的一致性；还不是全代码物理模型审计。

这个链条足以支撑“配置到结果表”的可追溯性，但不等于：

- `physics/` syndrome wrapping 已经被完整审计；
- finite-energy GKP 噪声、measurement noise 和 loss channel 已经与文献模型逐项一致；
- logical-error proxy 已经等价于真实 logical channel；
- fallback absence 已经被全仓库证明；
- 硬件路径已经参与了 benchmark。

## 5. 审稿人视角的主要缺口

1. **物理模型缺口**：TeX 中的 GKP syndrome model 是合理的论文表述，但当前尚缺 `physics/` 层 syndrome wrapping、lattice constant、finite-energy/noisy auxiliary state 和 logical-error criterion 的独立审计。
2. **配置字段缺口**：已有 YAML 和 runner 代码能说明 synthetic drift trajectory，但尚缺一份机器可读 table，把每个 config 字段映射到论文符号、单位、范围和默认值。
3. **泛化缺口**：四场景是 hand-designed frozen set，不是 holdout drift distribution。没有 random-walk、burst/reset、mixed covariance、oracle affine 或 wrapped-Gaussian baseline。
4. **统计缺口**：T24 是 paired seeds + `repeats=2`，只能写 descriptive mean/std，不能写 confidence interval、显著性检验或 strong statistical robustness。
5. **机制缺口**：teacher diagnostics 在 T24 中仍为空/零值；FR6/FR7 只能作为 descriptive mechanism support，不是 causal mechanism proof。
6. **硬件缺口**：real-board 当前仍是 `NO_GO` gate；`.tflite` 证据也只限 isolated current-host runtime，不能写成 HIL 或 deployment closure。

## 6. 对投稿稿的具体写作建议

### 建议加入主文或附录的桥接表

投稿稿应保留一张 `Theory-to-Configuration Bridge` 表，列：

- theoretical object；
- current implementation bridge；
- manuscript use；
- missing evidence before stronger claim。

该表能显著降低审稿人误读：它把 `\theta_t^{noise}`、`mock_signal`、T24 `comparison.csv`、hardware placeholders 和 missing physics audit 明确拆开。

### 建议替换的表达

| 风险表达 | 推荐表达 |
| --- | --- |
| physical drift benchmark | controlled synthetic drift benchmark |
| hardware-aware validation | hardware-facing boundary / future measurement protocol |
| logical error rate of the GKP code | final logical-error proxy under the software-HIL protocol |
| CNN decoder improves GKP decoding | hybrid residual calibration improves the locked software-HIL ranking |
| four scenarios prove drift adaptation | four scenarios probe selected adaptation demands |
| statcalib validates the mechanism | statcalib supports the general affine-contract interpretation as an extension lane |

## 7. 后续材料清单

若要把当前稿件从 bounded manuscript draft 推向更强投稿，需要补：

1. `physics/` GKP/noise/logical-error audit：syndrome wrapping、\(\sqrt{2\pi}\) convention、noise stream、decision boundary。
2. machine-readable theory-to-config ledger：config field、symbol、unit、range、scenario role、default/protocol value。
3. expanded benchmark protocol：holdout drift families、oracle/known-noise/wrapped-Gaussian/nearest-lattice baselines、predeclared uncertainty protocol。
4. per-row provenance manifest：scenario/mode/repeat/seed/config hash/artifact hash/runner version/environment。
5. adaptation trace source data：drift trajectory、estimated state、committed \(K,b\)、commit cadence、stale/fallback/saturation events。
6. hardware replacement pack：board logs、bitstream/RTL hash、DMA/MMIO contract、fixed-point vectors、latency/resource/power metrics、source-vs-board agreement。

## 8. 当前可写结论

当前最稳的结论是：

> Under a locked mock-backed software-HIL protocol, the hybrid residual-\(b\) calibration branch ranks first across four controlled synthetic drift scenarios while preserving a deterministic affine fast-path contract. The result is traceable to T24 artifacts, but remains bounded by descriptive uncertainty, limited scenarios, incomplete physical-noise audit and absent hardware validation.

这也是投稿稿当前应坚持的上限。任何 stronger paper claim 都应等待后续审计或预声明实验补齐。
