# T0.1.1 研究对象冻结：repeated-memory single-mode square approximate GKP

**Task ID：** `T0.1.1`  
**日期：** 2026-07-14  
**状态：** `Done`  
**文档角色：** 主对象 scope contract；后续 task 不得静默扩大此边界。

## 1. 冻结结论

本项目第一篇论文和 `docs/new_task_board.md` 的主线研究对象冻结为：

> 在 repeated quantum-memory error correction 场景中，研究单个振子模式编码一个逻辑量子比特的 square-lattice approximate GKP code；经典侧根据多轮 syndrome/history 估计非平稳噪声与离散健康状态，并通过可部署的低延迟 fast path 执行解码、frame/correction 或安全 fallback。

这里的 `approximate GKP` 明确指有限能量、有限 squeezing 的 GKP 态或与其协议对齐的有效模型。主线科学问题是“在漂移、测量误差、reset/leakage 和控制非理想下，经典自适应解码/控制能否缩小 static baseline 到不可部署 oracle/bound 的差距”，而不是优化 GKP 态制备本身。

## 3. 周期语义

主线的抽象 cycle 固定为：

```text
previous residual / frame
        -> idle + channel/control noise
        -> syndrome extraction and measurement
        -> analog/event observation
        -> decoder/controller decision
        -> correction or frame update / fallback
        -> logical tracking and next-cycle memory
```

T0.1.1 只冻结这个平台无关的数据流，不冻结 superconducting cavity、transmon、sBs、sharpen–trim 或具体板卡的实现细节；它们分别由 T0.1.2、T2.0 和 T1.4/T6 冻结。

## 4. 主线、验证线和排除项

| 分类 | 内容 | 处理规则 |
| --- | --- | --- |
| 主线 | single-mode square approximate GKP repeated-memory QEC；drift/regime-aware classical decoding/control；host + FPGA 双回路 | 可进入主要模型、baseline、实验和论文 claim，但必须逐层满足证据门 |
| 独立验证线 | finite-cutoff Fock model、noise-transfer surrogate、channel-recovery bound、secondary protocol reproduction | 用于交叉验证或上界，不得冒充可部署 decoder 或真实实验 |
| 未来兼容 | 将 inner-GKP 输出交给 surface/QLDPC 等 outer decoder 的接口 | 只允许作为 future-compatible interface，不进入第一篇论文主性能排名 |
| 明确排除 | outer surface/QLDPC code 的联合主线、多模/多振子格码、Bell-pair GKP 主线 | 若未来需要，必须另立 task/sidecar，不能在当前任务中隐式加入 |
| 明确排除 | GKP state-preparation pulse/optimal-control 作为主要贡献 | 可把制备误差当输入噪声或文献参数，但不优化物理制备协议 |
| 明确排除 | 用 single-mode 结果声称 surface-code threshold、fault-tolerant threshold 或真实 beyond-break-even | 只能使用 operational boundary、simulation-derived coherence/lifetime gain 等受限措辞 |
| 明确排除 | 未有证据的真实 cavity/transmon、微波链、真实高速 ADC 或板级量子闭环 claim | 软件、综合、板级数字控制和 HIL 证据必须分层表述 |

## 5. 单位与晶格约定

当前代码以 `LATTICE_CONST = sqrt(2*pi)` 作为本地 modular period，并以半周期作为逻辑跨格判据。这可以对应一种常见 quadrature normalization，但现有代码与任务板后续公式尚未给出统一的 `[q,p]`、vacuum variance、stabilizer spacing、logical spacing 对照表。

因此本 task **不把 `sqrt(2*pi)` 本身认证为跨模块已校验的物理单位约定**。T1.1.1 必须显式冻结：

- quadrature commutator 与 vacuum variance；
- stabilizer spacing、logical spacing、syndrome period 和 decision boundary；
- `physics/gkp_state.py`、`physics/syndrome_measurement.py`、`physics/logical_tracking.py` 的一致性；
- 解析逻辑翻转概率与 Monte Carlo 的同一单位约定。

在该验收通过前，禁止把当前数值阈值直接与采用另一归一化的论文数值比较。

## 6. 现有代码复用与真实性边界

本 task 优先复用了现有项目代码，没有另建 demo 仿真器：

1. `physics/gkp_state.py`：已有近似态、`delta`/squeezing 转换、解析 Wigner 和可选 Strawberry Fields 路径；
2. `physics/noise_channels.py`：已有 loss/thermal/displacement/phase 的 Wigner-level 代理；
3. `physics/syndrome_measurement.py`：已有 modular syndrome、测量效率、shot noise 和 ancilla-error 代理；
4. `physics/error_correction.py`：已有线性 decoder 和多轮 QEC 入口；
5. `physics/logical_tracking.py`：已有 repeated residual tracking、windowed LER 和 `full_qec`/legacy 两条路径；
6. `cnn_fpga/`：已有工程化数据、模型、runtime/HIL 基础，后续 task 应在此基础上扩展，不另起脱离主线的玩具实现。

上述映射只证明“可复用起点存在”，不证明其物理正确性、数值收敛性或论文级强度。尤其是解析 Wigner、Wigner-level noise、linear decoder 和 `simplified` compatibility branch 都必须在对应 task 中接受独立测试与交叉验证。

## 8. 失败分支

1. 若 T1.1 发现单位/晶格约定不一致：先统一常量、公式和测试，再允许任何性能对比；不得以兼容性为由保留两套无标注单位。
2. 若 T1.2/T2.3 发现当前解析近似不能复现有限能量趋势：保留主对象，替换或降级模型；不得把代理结果写成态级验证。
3. 若 T2.0 发现 sBs 证据不足：可回退到 protocol-aligned syndrome model，但必须降低实验协议 claim。
4. 若后续结果只有 outer-code 或 multimode 才成立：本主线判定证否，相关方向另立 sidecar；不得静默改写 T0.1.1。
5. 若 state preparation 成为主要瓶颈：登记风险并作为独立输入/校准任务处理，不把制备优化塞入 decoder/controller task。

## 9. 允许和禁止的论文表述

允许：

- `single-mode square approximate GKP quantum-memory simulation`；
- `experiment-informed`、`protocol-aligned`、`simulation-derived`；
- `drift/regime-aware classical decoding or control`；
- 在同一模型与成本口径下报告 oracle gap、logical lifetime 或 operational boundary。

禁止：

- `surface-GKP threshold`、`fault-tolerant threshold`；
- 用单模结果代表多模/外层码结果；
- 把解析代理写成真实 GKP experiment；
- 把 synthesis estimate、软件 HIL 或低成本 FPGA 数字控制测量写成真实 cavity/transmon 闭环；
- 把 state-preparation optimization 写成当前项目贡献。
