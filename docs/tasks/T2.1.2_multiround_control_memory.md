## 1. 输入与执行方案

输入为 T2.1.1 `ObservedSyndromeStep`、T2.0 `PauliFrame/PairedSyndrome`、旧 `LogicalErrorTracker/FastLoopEmulator` correction semantics、真实 `ParamBank.active_version` 和任务板八类 required state。

执行前把通过标准拆成：

1. residual：从 modular observation 建连续 multi-round estimate，必须跨 wrap boundary；
2. action：上一 correction 必须是实际执行值，符号与现有 fast loop 一致；
3. uncertainty/frame：q/p confidence、Pauli XOR、phase modulo 都显式；
4. history：X/Z e-run、leakage run 与 deadline run/total 独立且饱和；
5. runtime：bank version 单调，能消费真实 stage/commit 结果；
6. isolation：只允许 observed step，hidden/truth 类型拒绝；
7. transactional：坏 cycle/counter/residual/version 不留下半更新。

## 2. 实际完成内容

- 新增 frozen `ControlDecision/ControlMemoryState/ControlMemoryUpdate/Trajectory`；
- 实现以 previous post-action estimate 为参考的 nearest periodic lift；

- 保存 previous correction、q/p confidence/min confidence、Pauli/phase frame；
- recompute 并冗余核验 e/leakage runs，所有 run/count 饱和；
- 保存 bank version、version-change、deadline current/run/count 与 control mode；

- 真实 `ParamBank` `0->1` atomic commit 集成；
- reset、segmented append、deployable records 和 public exports；
- protocol hierarchy 增加 machine-readable memory contract/update。

## 3. 反简化检查

- 发现并修复首版 correction 符号与现有 `LogicalErrorTracker` 相反的问题；
- `0.49 lambda -> -0.49 lambda` 验证为连续 `0.51 lambda`，不是错误跳回；
- full `SyndromeStreamStep` 直接拒绝，不能靠调用者自觉避免 truth leakage；
