## 1. 执行方案

本 task 不把论文数字直接复制成项目配置，而按四步执行：

1. 对三篇核心全文做正文/补充材料级参数抽取，并记录精确本地行锚；
2. 用 DOI-first 规则把 formal record 与 preprint 去重，正式版本优先；
3. 把一手事实、仓库 reading-card secondary、项目当前假设、真实待校准值分成四类；
4. 对每条记录增加 normalization、allowed use、forbidden transfer 和 calibration gate，
   再用机器测试直接复核原文、YAML 和 live constant。

文献检索与版本核验采用 `nature-academic-search` 的 multi-source search、DOI dedup 和
citation verification 规则；本地不存在可调用的学术 MCP 时，使用该 skill 的 fallback
脚本核验 formal DOI。其直接影响是：Sivak 与 Lachance 的正式记录优先于 arXiv，secondary
reading card 没有被升格为 primary fact。

## 3. 实际完成内容

### 3.1 机器 registry

建立 8 个 source records、51 个 parameter records：

- `30` 条 `literature_fact`：只来自本地一手正文/补充材料；
- `3` 条 `secondary_reference`：Wan memory-assisted 与 Lachance autonomous 邻域；
- `9` 条 `modeling_assumption`：直接绑定当前 YAML/constant；
- `9` 条 `pending_calibration`：每个必需类别各一条，值均为 `null + gate`。

每条记录有唯一 ID、类别、值/单位、事实 scope、source path/line/fragment、normalization、
allowed/forbidden transfer 和 calibration gate。Markdown 以 machine marker 与 JSON 一一同步。

### 3.2 关键口径冻结

- Campagne：square four-round sharpen/trim、1.1 us CD、700 ns readout、`±y` syndrome、
  fidelity 下界、conditional reset、DAC drift、`f` leakage、7.4--9.5 dB 与 logical lifetime；
- Sivak：`4.924 us` constituent 与 `9.848 us` full X+Z cycle、读出链时序、g/e/f、
  partial fidelity、reset、1--2 week retraining、leakage memory/rate、gain/lifetime；
- Puviani：`10/5 us` model cycle、理想 projective g/e、numerical reset、leakage/SPAM omission、
  scoped Delta/noise levels、best-of-20 numerical lifetime；
- GKP：只取 Gaussian peaks + Gaussian envelope 的结构性 finite-squeezing 事实；
- 项目：`5 us / 2048 / 20 ms / sigma=0.03 / ratio=0.55 / ancilla=0.01 /
  efficiency=0.95 / delta=0.3 / sqrt(2*pi)` 全部标为 assumption。

### 3.3 缺失证据 fail closed

以下字段没有用文献数值或 synthetic config 填补：

- 项目真实 protocol binding；
- 低价板闭环 p50/p95/p99/max timing；
- quantum readout class schema 与 confusion matrix；
- reset duration/failure；
- empirical drift distribution；
- leakage taxonomy/rate/memory；
- paper-to-model normalization map；
- same-system physical break-even/lifetime。

## 4. 反简化复核与修正

初版通过 focused tests 后，又做了一轮 source-internal audit，发现两个普通摘录表容易漏掉的
问题并补回：

1. Sivak 同一 highest-gain SBS 的 prose 为 `1546 ns`，Table S3 层和为 `1548 ns`；
   registry 保留两值和 `2 ns` 差异，不擅自“修正”。
2. Puviani low/medium/high `Ts/T1/T2` 是按 `10 us` model cycle 换算的 numerical
   assumptions；不能只抄绝对微秒值并包装成实验测量。

同时锁定：Campagne `>99%` 与 `99.5%` 不是 confusion matrix；Sivak 当前文本没有完整
`F_f`/off-diagonal matrix；Puviani measurement/reset/leakage 理想化和 best-of-20 selection
必须进入 claim caveat；reading-card secondary 不得支持强数值 claim。

因此本 task 不是 demo 级“论文参数汇总”：测试会逐条读取 source line，直接比对 current
YAML/constant，并检查缺失值保持 fail closed。
