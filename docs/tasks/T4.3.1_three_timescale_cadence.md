# T4.3.1：定义 fast/event/slow 三种更新频率

## 状态

Done（2026-07-15）。

## 输入与通过标准

输入为 T4.2.1--T4.2.4 integer fast path、`DualLoopScheduler`、`ParamBank`、HIL 配置与 T1.4.3
双域/三时间尺度 contract。通过标准是 per-cycle/event/window/slow/commit/recalibration cadence 明确，用真实执行
trace 连接 fast 与 host update，对全部 onset phase 量化 lag，且不把软件配置冒充硬件。

## 实际完成

新增 integer-epoch cadence runtime 和 14-gate validation；冻结 5 us fast、1-cycle local event、2048-sample/
4000-cycle window、20 ms slow、995 us reference service、1-cycle commit、60 s/end-run recalibration due。
用真实 scheduler、ParamBank 和 T4.2 integer path 回放 leakage→window→slow→stage→commit→first-use。

深审计发现 T4.2.3 默认 age 64 与 4000-cycle cadence 冲突；为 fast path 增加可配置 age gate，并在两份生产
HIL 配置冻结 8192 cycles，允许一个 slow interval 缺口后继续、第二个缺口后 fail closed。

## 验证与非 demo 审计

4000 phases×2 evidence policies 共 8000 rows。first-influenced lag 为 `1.000--20.995 ms`，median
`10.9975 ms`；full-post-change 为 `11.235--31.230 ms`，median `21.2325 ms`。reference trace 在
2041 local hold、2048 发窗/启动、2247 finish/stage、2248 commit/first-use，独立重跑 hash 一致。

14/14 production gates、26 focused、106 focused+adjacent；显式全量 `tests/` 为
`1404 passed, 14 skipped, 4 failed`，4 个失败仍仅为 R-N012。相邻回归在重新生成 T4.2.4 source-bound
artifact、同步 HIL YAML 引起的 paper-parameter registry 行锚后通过。
