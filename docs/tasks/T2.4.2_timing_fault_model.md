## 执行方案与实际完成

1. 扩展 scheduler，加入显式 FIFO overflow/drop-oldest provenance、外部 burst、通信 pause 起止与
   paused cycles、端到端 window-age deadline、最后 fast latency 和完整 snapshot counter。
2. 修复真实缺陷：`ParamBank.stage_update` 原先会静默覆盖未提交 update；现在第二 writer fail
   closed，并通过 scheduler 输出结构化 conflict event。
3. 构造 7 个相互隔离/组合场景。所有场景共享同 seed physical trace，slow estimator 只读 observed
   window mean；fast miss 的 hold-last 只存在于 stress effect model，不伪装成 runtime safety closure。
4. 同时量化 fast action、fresh parameter、end-to-end 三类 availability 和 standard-binning LER；
   使用 8 个 paired seeds、每组 64,000 cycles、10,000 次 paired cluster bootstrap。
5. 门槛强化为逐 seed 故障覆盖；另验证孤立 rejected conflict 与 reference 精确中性、version 单调、
   conflict 0 次落盘、所有数组有限、非板测标签和源码 hash。
6. 生成完整 JSON、56 行逐 seed CSV 和中文方法/结果报告。

CRC/age/CAS/ack 与 late-action suppression 仍开放。新增 R-N045，跟踪 synthetic stress law/hold-last/
freshness 定义未设备标定导致的 effect-size 外推风险。

当前结论不依赖这些尚未完成的证据。

## 对论文 claim 的影响

允许写：paired software timing stress 能逐 seed 检测五类故障，并在明确模型条件下量化 LER 与三层
availability。禁止写：目标板 measured availability、hard-real-time guarantee、device-calibrated fault
rate 或 quantum experiment LER。
