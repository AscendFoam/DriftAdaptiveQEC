## 2026-07-18 真板前收口增量

在不改变 `Blocked` 状态的前提下，补齐了“板到即测”的候选实现：

- 新增 40-byte request / 96-byte response 的 CRC32、sequence、version、reserved-bit、idempotent duplicate UART 协议；commit/config/posterior/fault/reset 等事件输入只在 `core_in_valid` 当拍产生一次脉冲，避免串口空闲期重复提交或重复故障。
- 新增 Tang Nano 20K 候选 UART PHY、板级 top 和候选 pin constraints。完整栈 CXXRTL 以 3 clocks/bit 加速协议时序，独立 PHY 以实际 27 MHz / 3 Mbaud 的 9 clocks/bit 验证；前者 6 个响应全部通过，后者收到 5 bytes 并正确计数 1 次 framing error。
- 深审发现原 128-byte 全状态响应和 exact replay 整帧缓存造成不必要的寄存器/路由膨胀；改为 96-byte 最小充分响应和显式 duplicate 状态，不重新执行、不消耗序号。DFF 由首版 P&R 输入的 4,811 降至 2,969。
- 目标 `GW2AR-LV18QN88C8/I7` 完成综合、P&R 和 `gowin_pack`：LUT4 `6532/20736`、DFF `2969/15552`、BSRAM `8/46`、后路由 Fmax `83.9701 MHz`，27 MHz 约束通过，并生成非空 `.fs` 候选。
- 新增机器可读 preboard manifest 和显式 host smoke。manifest 固定 `candidate_is_physical_evidence=false`、`board_programmed=false`、`physical_measurements_collected=false`；host wall-clock 只作诊断，不能代替 T6.1.3 source-to-action timestamp。

新增产物：`route_a_uart_protocol.py`、`route_a_uart_phy.sv`、`route_a_uart_board_top.sv`、候选 CST、`route_a_board_ready_preflight.py`、`route_a_board_uart_smoke.py`、`docs/t6_9_2_preboard_bitstream_candidate.json`、`docs/route_a_board_preboard_candidate.md` 及对应测试。

验证：preboard manifest 为 `PASS_PREBOARD_CANDIDATE_NOT_PHYSICAL_QUALIFICATION`；相关协议、preflight、原板测 blocker、最终 evidence gate 与任务板治理共 `23 passed`。逐帧 UART 会插入 host/link gap，不能冒充满速 `1e6`-cycle HIL；T6.4 仍需板上 streaming 或 autonomous trace path。
