## 输入、通过标准与失败分支

输入为任务板要求的 no correction、standard/autonomous sBs、static/top-K/decoder-oracle MAP、finite-energy
static、Bayesian、EWMA/Kalman、window、run-length、HMM、MF/FNN、指数递推、RNN teacher、student 和
control oracle，以及 T3/T4 的实现、artifact、术语合同与 T5.0.1/T5.0.2 secondary 边界。

通过标准不是把旧标量拼成大表，而是每个 required comparator 都有唯一 ID、可执行代码锚、证据状态、
decision target、information set、output、protocol/metric/time/compute/deployability contract，并只进入兼容
lane。缺项、hidden truth 泄漏、跨 lane 排名或 Knill/P-Steane 进入 sBs 主表时必须 fail closed。

## 执行方案与实际完成

先审计 T3/T4 全部基线，确认它们分属 decoder、protocol、controller、host estimator、component 与 oracle
不同目标。随后建立 19-comparator/8-lane machine registry，而不是一张 global leaderboard。

审计发现仓库没有真正的 no-correction protocol baseline，因此在 `physics/autonomous_sbs.py` 新增
`IdleMemorySimulator`：与 standard sBs 使用同 finite-cutoff 初态和 10 us 网格，只传播 cavity idle-loss，
所有 gate/measurement/reset/frame/update 计数严格为 0。它不是全零 outcome demo：final density 与 standard
sBs 最大差 `0.342927`，10 us 与 2×5 us channel semigroup 差 `1.11e-16`，并验证 trace/PSD。

finite-energy static 也没有只登记名字，而是在 registry runner 中实际执行五点、120k train/300k held-out
shrinkage harness。16 个既有 artifacts、19 个实现 fragments/hashes 和 28 个 lane memberships 均逐次验证。
