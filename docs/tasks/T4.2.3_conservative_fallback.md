# T4.2.3：设计 conservative fallback 和健康标志

## 状态

Done（2026-07-15）。

## 输入与通过标准

输入为 T4.2.1 image/version/MAP decision、T4.2.2 observed event FSM，以及 OOD、age、CRC/SHA readback、
deadline/reset signals。通过标准是所有 fault 都有确定动作和原因，blocking fault 不消费 MAP/不更新 frame/
不接受 version，恢复有 hysteresis，同时保留 no-truth 和 non-hardware 边界。

## 实际完成

新增可信 image registry、14-bit fault taxonomy、per-reason uint8 counters、status/primary/full trace，允许
T4.2.2 在 health fault 时接收 absent MAP 并安全推进 cycle。blocking fault 输出 `frame_hold_no_map`；leakage
走 hold/reset/ack；valid versions 可单调前进，rollback/unknown/mismatch 保持 last trusted version。

## 验证与深审计

20/20 production gates、28 T4.2.3 focused、126 focused+adjacent tests 通过；显式全量 `tests/` 为
`1363 passed, 14 skipped, 4 failed`，4 个失败仍仅为 R-N012 缺失旧 FR8/P4 文档。16×256=4,096 rows 覆盖 14 flags、阈值边界、
simultaneous faults、uint8 saturation、8-bank switch、两周期恢复、6-cycle/II=1 和 deterministic replay。
深审计没有把 bank 0 冒充自动 rollback：fallback 明确是 no-map frame hold；可信 registry 也从周期输入中
移出，避免 reported hash 自证可信。
