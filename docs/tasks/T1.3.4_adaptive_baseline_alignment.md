## 1. 要回答的问题

在继续任何 CNN 性能主张前，先回答一个更窄但必要的问题：仓库已有的可部署
Window Variance / EKF estimator 是否能在同一 synthetic drift trace 上，显著缩小 static MAP
与知道真实噪声状态的 model oracle MAP 之间的逻辑错误率差距。

本任务不是重新发明 estimator，也不把旧 P4 的 `oracle_delayed` 或“paired seeds”当作新
oracle contract。实现直接调用：

- `WindowVarianceBaseline.predict(histogram, window_id)`；
- `EKFBaseline.predict(histogram, window_id)`；
- `map_decode_2d` 作为 static/adaptive Gaussian MAP action；
- `oracle_map_2d` 作为不可部署 full-state model oracle；
- `compute_oracle_gap_metrics` 作为唯一 paired gap/CI contract。

## 2. 真实 API 与能力边界

现有 Window/EKF/UKF/PF 都只输出
`NoisePrediction(sigma, mu_q, mu_p, theta_deg)`。其可表示的 covariance 子空间为

\[
\Sigma = R(\theta)
\operatorname{diag}\!\left(\sigma^2,(r\sigma)^2\right)
R(\theta)^\mathsf{T},
\]

其中 `r=sigma_ratio_p` 固定。T1.3.4 将 prediction 显式映射到这个二维 Gaussian
子空间；主通过场景固定 `loss_gamma=0`、`p_outlier=0`。因此本任务证明的是已有 baseline
在其可识别子空间内可利用 drift gap，不证明它能估计完整 `DriftState`。

旧 P4 的两类路径没有被误用：

- `oracle_delayed` / `_compute_oracle_track` 是窗口四参数到 `(K,b)` 的参考轨迹，不是
  `physics/oracle_map.py` 的 full-state decoder oracle；
- `--paired-seeds` 只保证共同随机数，不保证三种 decoder 使用同一份逐样本
  syndrome/truth/failure trace。

## 3. 冻结的 causal benchmark

| 项目 | 默认值 |
| --- | --- |
| drift | 24 windows 的 pre-registered step，`change_step=8` |
| calibration | 6 个独立 pre-drift windows |
| observation/evaluation | 每窗各 3000；两者独立 |
| histogram | `48 x 48` folded syndrome raw counts |
| before | `mu=(0,0)`，major sigma `0.18 lambda`，theta `0 deg` |
| after | `mu=(0.20,-0.15) lambda`，major sigma `0.22 lambda`，theta `15 deg` |
| axis ratio | `r=0.55` |
| seed | `20260714` |
| ratio bootstrap | 3000 次八类联合 outcome multinomial bootstrap |

每个窗口严格按以下次序执行：

1. 从当前真实 `DriftState` 只采样一次 evaluation buffer；
2. static、Window、EKF 与 oracle 全部读取同一 buffer、同一 syndrome 和同一 truth parity；
3. 完成当前窗口 decision 后，另采 observation buffer 并构造 histogram；
4. 调用真实 baseline `predict`，但 prediction 只能用于下一窗口。

因此 change window 本身仍使用最后一个 before-regime estimate，不能把当前窗 histogram
回填到当前窗。首窗使用独立 calibration prediction。每个 evaluation window 和整条 trace
都生成 SHA-256 指纹，避免把“同 seed 重跑”误写成“同 trace”。

## 4. 默认验收结果

72,000 个严格配对 evaluation samples 的结果为：

| Decoder | 逻辑错误率 | 相对 static 绝对改善 | static-to-oracle gap closed |
| --- | ---: | ---: | ---: |
| Static calibration MAP | 0.061389 | — | 0 |
| Window Variance + MAP | 0.022639 | 0.038750 | 0.775000 |
| EKF + MAP（预注册 primary） | 0.025319 | 0.036069 | 0.721389 |
| Full-state model oracle | 0.011389 | — | 1 |

配对不确定性：

- static-oracle gap：`0.050000`，95% CI `[0.048267, 0.051733]`；
- static-EKF improvement：`0.036069`，95% CI `[0.034658, 0.037481]`；
- EKF closed fraction bootstrap CI：`[0.704449, 0.737794]`；
- 3000/3000 bootstrap replicates 具有正分母，`ratio_ci_reliable=True`；
- EKF 的 static-only / EKF-only discordant failures 为 `2690 / 93`，signed
  McNemar `z=49.23`。

分 regime 复核：

| Regime | N | Static | Window | EKF | Oracle |
| --- | ---: | ---: | ---: | ---: | ---: |
| before | 24,000 | 0.005500 | 0.005375 | 0.005458 | 0.005417 |
| after | 48,000 | 0.089333 | 0.031271 | 0.035250 | 0.014375 |

这说明 adaptive gain 来自 drift 后的失配修复，静态区间没有靠明显退化换取总体改善。
整条默认 evaluation trace 指纹为
`975a606105be9ba2b28f81466367d38142e941515276f0556f7dde1aae770439`。

## 5. 测试与反简化复核

新增 18 个 pytest case，覆盖：

- 默认 72k 样本 acceptance gate、positive stable denominator 和 reliable ratio CI；
- 四种 decoder failure count 到最终 rates/metrics 的逐项账目一致性；
- change window 一窗延迟，禁止 current-window target leakage；
- 短/长运行在相同 seed 下的原始 window-trace hash、prediction 和 failure 前缀完全一致；
- 同配置重复运行整个 dataclass 结果逐字段相等；
- seed child range、histogram size、sample workload、参数物理范围和错误对象失败分支；
- 同一 materialized evaluation buffer 同时生成四组 failure arrays，而不是四次重采样。

验证结果：

```text
focused T1.3.4:                    18 passed
T1.3 + existing baseline adjacent: 69 passed
explicit tests/:                 190 passed, 4 failed
```

4 个失败仍仅来自 R-N012：缺少
`docs/fr8_statcalib_extension_lane_benchmark.md` 和
`docs/P4_benchmark_formal_protocol.md`，与本任务代码无关。

| 伪实现风险 | 处理结果 |
| --- | --- |
| 自写简化 estimator 冒充旧 baseline | 否；直接实例化 Window/EKF 真实类并调用 `predict` |
| 当前窗观测用于当前窗 decision | 否；固定一窗 causal delay，并有 step-lag test |
| 三种 decoder 各自重采样 | 否；同一 evaluation ndarray 生成四组 decisions |
| 只报告 aggregate rate | 否；保留每窗 failure count、逐窗/全局 trace hash 和 paired outcomes |
| 只给 point closure | 否；paired CI、McNemar、bootstrap ratio reliability 均通过 |
| 通过手选 adaptive method | 否；EKF 在实现前预注册为 primary，Window 同时完整报告 |
| 把 Gaussian 子空间写成 full drift | 否；loss/outlier/general covariance 能力缺口显式降级 |
| 无界配置导致 benchmark 假死 | 否；sample、window、histogram、seed 和总 workload fail closed |

结论：T1.3.4 的“存在可利用 gap”通过，不需要为了制造 gap 事后修改 metric 或 decoder。

## 6. 论文 claim 边界

当前只允许写：在预注册、因果、一窗延迟的 Gaussian step-drift synthetic scenario 中，现有
EKF/Window baseline 显著缩小 static MAP 到 assumed-model oracle MAP 的 logical-error gap。

当前禁止写：

- baseline 已识别 loss、outlier、leakage 或任意 covariance drift；
- oracle 是 finite-energy/protocol-aware optimal recovery；
- 该结果已覆盖七类 drift 或真实装置时序；
- CNN 将必然优于这些 baseline；
- 本 synthetic 结果是 FPGA 或量子硬件实测。

R-N020 继续跟踪 folded syndrome 的线性矩偏置、固定轴比、loss/outlier 不可辨识和单 step
场景外推问题；T2.1、T3.2 与 T5.1 的正常任务会扩大到 protocol-native stream、强 adaptive
baseline 和完整 scenario matrix。
