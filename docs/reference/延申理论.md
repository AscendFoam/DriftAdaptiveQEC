你说的

[
\hat e = K s + b
]

更准确地说是 **GKP syndrome 的仿射线性估计器**，也常被文献叫作 **linear estimation** 或 **syndrome-informed displacement**。这里：

* (s)：测得的 GKP syndrome，通常是连续值，并且是“模格点”的结果；
* (K)：把 syndrome 映射到误差估计的增益矩阵；
* (b)：偏置项，可能来自 syndrome 的零点校准、非零均值噪声，或某个 GKP 格点分支的 offset；
* (\hat e)：估计出的相空间位移误差；
* 实际恢复操作通常是施加反向位移 (-\hat e)。

文献上最接近这个形式的是 GKP oscillator-to-oscillator codes 里的 **linear estimation**。Brady 等人的 GKP 综述明确说，解码时要从 ancilla 的 stabilizer syndrome 推断 data mode 上的实际噪声，然后根据估计函数 (f(s)) 对 data 施加 syndrome-informed displacement；其中 linear estimation 就是令估计函数对 syndrome 线性。([arXiv][1])

## 1. 为什么 GKP 解码天然会出现 (K s+b)

GKP syndrome 不是普通 qubit 稳定子码里的 0/1 syndrome，而是连续变量相空间中的模测量。对多模 GKP，误差可以写成相空间位移向量

[
e =
(\Delta q_1,\ldots,\Delta q_n,\Delta p_1,\ldots,\Delta p_n)^T.
]

综合测量本质上测的是某些相空间线性组合：

[
s \approx H e \pmod{\Lambda}.
]

这里 (H) 是由 GKP 稳定子、Gaussian 电路、homodyne 测量共同决定的矩阵，(\Lambda) 是 GKP 的 syndrome 周期格。Roy、Pousset、Royer 的多模 GKP 论文也强调：多模 GKP 的稳定子测量需要测量 quadrature 的线性组合，并且是 modulo 形式；实际实验中通过辅助 GKP 态和 Gaussian 耦合把这些信息传播到辅助模再测量。([arXiv][2])

如果噪声足够小，可以先忽略 “(\pmod{\Lambda})” 的折叠，于是 syndrome 近似满足线性高斯模型：

[
s = H e + \eta,
]

其中 (\eta) 是测量噪声、辅助 GKP 态有限压缩噪声、homodyne 噪声等。此时最自然的估计器就是线性最小均方误差估计器：

[
\hat e = K s + b.
]

这就是 (K@s+b) 的来源：**Gaussian 电路让误差线性传播，高斯噪声让最优的局部估计器变成线性估计器。**

---

## 2. (K) 的统计意义：LMMSE 增益矩阵

假设 data 上真正想估计的误差是 (e_d)，测得的 syndrome 是 (s)。在小噪声近似下，把二者看成联合高斯变量：

[
\begin{pmatrix}
e_d\
s
\end{pmatrix}
\sim
\mathcal N
\left[
\begin{pmatrix}
\mu_e\
\mu_s
\end{pmatrix},
\begin{pmatrix}
\Sigma_{ee} & \Sigma_{es}\
\Sigma_{se} & \Sigma_{ss}
\end{pmatrix}
\right].
]

那么最小均方误差的线性估计是

[
\hat e_d
========

\mu_e
+
\Sigma_{es}\Sigma_{ss}^{-1}(s-\mu_s).
]

写成 (K s+b)：

[
K=\Sigma_{es}\Sigma_{ss}^{-1},
]

[
b=\mu_e-K\mu_s.
]

如果噪声是零均值、syndrome 已经正确居中，通常 (b=0)。如果实验或模拟中存在 syndrome offset、homodyne bias、finite-squeezing 引起的均值漂移，或者你在某个格点分支上展开 modulo syndrome，那么 (b\neq0)。

这和 Brady 等综述中的说法一致：linear estimation 是把 data 噪声写成 syndrome 的线性函数；其合理性来自忽略 GKP 格点模结构后的 Gaussian 近似。该综述还指出，MMSE estimator 更一般，因为真实的 GKP syndrome 分布不是单个高斯，而是高斯和的非高斯分布。([arXiv][1])

---

## 3. (b) 的一个重要来源：GKP syndrome 的“格点展开分支”

GKP syndrome 有周期性。例如一维情形可写成

[
s = e \pmod{\sqrt{\pi}},
]

也就是

[
e = s + m\sqrt{\pi},\qquad m\in\mathbb Z.
]

所以同一个 syndrome (s) 对应无穷多个候选误差：

[
s,\quad s+\sqrt{\pi},\quad s-\sqrt{\pi},\quad s+2\sqrt{\pi},\ldots
]

如果你固定某个分支 (m)，估计器就是

[
\hat e_m = K(s+m\sqrt{\pi}) = K s + K m\sqrt{\pi}.
]

于是

[
b_m=K m\sqrt{\pi}.
]

这解释了为什么实际 GKP 解码里经常不是单一全局线性函数，而是**分段仿射函数**：

[
\hat e =
K s + b_m,
]

其中 (m) 由“最近格点”或“最大似然分支”决定。

这也连接到最近格点解码。Lin、Chamberland、Noh 的多模 GKP 论文把通用多模 GKP 解码描述为：先找与 syndrome 兼容的候选位移，再在辛对偶格中找最近格点；一般非结构化 GKP 码的精确最近点解码复杂度随模数指数增长。([arXiv][3])

---

## 4. 线性估计器与完整 ML/MMSE 解码的关系

完整 GKP 解码不是单纯 (K s+b)，而是要处理 syndrome 的周期折叠。真实后验分布大致是很多高斯分量的和：

[
P(e\mid s)
\propto
\sum_{m\in\mathbb Z^r}
\exp\left[
-\frac12
(e-\mu_m(s))^T
\Sigma_m^{-1}
(e-\mu_m(s))
\right].
]

每个分量的中心 (\mu_m(s)) 都是一个仿射函数：

[
\mu_m(s)=K s+b_m.
]

因此：

* **linear decoder**：只取一个固定或近似的 (K s+b)；
* **piecewise-linear / nearest-lattice decoder**：先选最可能的格点分支 (m^*)，再用 (K s+b_{m^*})；
* **MMSE decoder**：对所有分支加权平均：

[
\hat e_{\rm MMSE}
=================

\sum_m w_m(s)(K s+b_m).
]

所以 (K@s+b) 可以看成 MMSE 解码的局部线性化，或最近格点解码在某个 Voronoi cell 内的仿射表达。Wu、Brady、Zhuang 的工作进一步给出了 GKP oscillator-to-oscillator code 的 MMSE estimator，并指出它比 linear estimator 更优；Brady 等综述也明确总结了这一点。([Quantum][4])

## 5. 一个最简单的一维例子

假设一个 GKP ancilla 测得

[
s = e+\eta \pmod{\sqrt{\pi}},
]

并且先忽略 modulo 折叠。设

[
e\sim\mathcal N(0,\sigma_e^2),
\qquad
\eta\sim\mathcal N(0,\sigma_\eta^2),
]

则

[
s=e+\eta.
]

线性最小均方估计为

[
\hat e
======

\frac{\sigma_e^2}{\sigma_e^2+\sigma_\eta^2}s.
]

所以这里

[
K=\frac{\sigma_e^2}{\sigma_e^2+\sigma_\eta^2},
\qquad
b=0.
]

含义很直观：

* 如果 syndrome 很可靠，(\sigma_\eta^2\ll\sigma_e^2)，则 (K\approx1)，相信测量值；
* 如果 syndrome 很吵，(\sigma_\eta^2\gg\sigma_e^2)，则 (K\approx0)，不要过度修正；
* 如果有测量偏置 (\mu_s\neq0)，则加入 (b=-K\mu_s+\mu_e)。

真正的 GKP 情况还要考虑

[
s=e+\eta-m\sqrt{\pi}.
]

固定 (m) 后：

[
\hat e_m
========

# K(s+m\sqrt{\pi})

Ks+Km\sqrt{\pi}.
]

这就是最直观的 (K@s+b)。

## 6. 多模情形：(K) 学到的是误差相关性

多模 GKP 或 GKP-O2O 码中，Gaussian 编码/解码电路会把 data 噪声和 ancilla 噪声相关起来。Brady 等综述描述了这一点：解码的第一步是施加 Gaussian transformation，使 data 与 ancilla 的初始信息解耦，但让它们的 additive noise 相关；随后通过 GKP-assisted homodyne measurements 得到 syndrome，再用估计函数 (f(s)) 估计 data 噪声。([arXiv][1])

因此 (K) 不是任意矩阵，它包含了：

1. 编码矩阵 / symplectic 矩阵；
2. 噪声协方差；
3. syndrome 测量矩阵；
4. data 与 ancilla 噪声的相关性；
5. 各模 (q,p) 象限之间的耦合。

Roy、Pousset、Royer 的 noisy auxiliary GKP 解码进一步强调，辅助 GKP 态的噪声会污染 syndrome，而且 storage shift 与 measurement shift 之间存在相关性；利用这些相关性可以显著降低逻辑错误率。([arXiv][2])

在线性估计里，这些相关性正是通过

[
K=\Sigma_{es}\Sigma_{ss}^{-1}
]

进入解码器的。

## 7. 它和最近格点 / CVP 解码有什么区别？

可以这样理解：

### 最近格点解码

解的是离散优化问题：

[
m^*
===

\arg\min_m
|s+\lambda_m|_{\Sigma^{-1}}^2,
]

然后施加相应修正。这是 GKP lattice decoding / closest vector problem 的形式。Lin、Chamberland、Noh 指出，通用多模 GKP 码的 closest point decoding 一般指数复杂，但某些结构化 GKP 码可以线性时间精确解码。([arXiv][3])

### (K s+b) 线性解码

不显式搜索全部格点，而是把 syndrome 当作一个连续观测量，直接做线性回归式估计：

[
\hat e=Ks+b.
]

它速度极快，复杂度大约是矩阵乘法；如果 (K) 稀疏，甚至可做到近线性复杂度。但代价是：它只能很好处理“小噪声、单一格点分支占优”的区域。跨越 GKP 决策边界时，单个全局 (K s+b) 会失效，因为 syndrome 的 modulo 折叠必须被非线性地展开。

## 8. 如果 (K,b) 是训练出来的，它在学什么？

如果你看到代码里直接写：

```python
e_hat = K @ s + b
```

那么它可能有两种来源。

第一种是解析来源：

[
K=\Sigma_{es}\Sigma_{ss}^{-1},
\qquad
b=\mu_e-K\mu_s.
]

这是 LMMSE / Gaussian approximation。

第二种是数据驱动来源：给定训练样本 ((s_i,e_i))，最小化

[
\min_{K,b}
\sum_i
|e_i-(Ks_i+b)|^2.
]

这就是一个单层线性网络。它会学习 syndrome 到真实误差之间的最佳线性关系。如果训练数据包含不同 GKP 格点分支，但模型只有一个 (K,b)，那它学到的是平均意义下的线性近似；如果模型先按最近格点、syndrome cell、logical sector 分类，再给每类一个 (K,b)，它就变成分段仿射 decoder。

## 9. 总结一句话

(K@s+b) 型 GKP 解码的核心是：

> 把 GKP syndrome 看成对相空间位移误差的带噪线性观测，在忽略或局部展开 modulo 格点结构后，用 LMMSE/线性回归估计真实位移误差，再施加反向 displacement。

它的优点是快、可微、可训练、适合实时反馈；缺点是单个全局仿射映射不能完整处理 GKP 的格点周期性。更精确的 GKP 解码需要在多个 lattice branch 之间做最大似然、最近格点或 MMSE 加权，而这些方法可以看成许多个 (K s+b_m) 局部仿射估计器的组合。

[2]: https://arxiv.org/html/2510.12677v1 "Decoding Multimode Gottesman-Kitaev-Preskill Codes with Noisy Auxiliary States"
[3]: https://arxiv.org/abs/2303.04702 "[2303.04702] Closest lattice point decoding for multimode Gottesman-Kitaev-Preskill codes"
[4]: https://quantum-journal.org/papers/q-2023-08-16-1082/ "Optimal encoding of oscillators into more oscillators – Quantum"

> **CNN 不直接做 GKP 解码，而是学习“当前噪声环境下，最合适的线性/仿射估计器参数”**，即
> [
> (K,b)=g_\phi(\text{noise features / syndrome history / calibration map}),
> ]
> 然后用
> [
> \hat e = K s+b
> ]
> 估计 GKP 相空间位移误差，并施加反向 displacement。

我没有找到一篇文献正好以“CNN 输出 (K,b) 然后做 GKP 线性解码”为标题的论文；但这个方案可以由三条成熟文献脉络自然推出：**GKP 的 linear/MMSE estimation**、**有限能量近似 GKP 的噪声参数漂移建模**、以及 **CNN/神经网络 syndrome decoder**。

## 1. 你提出的结构本质上是“条件线性 GKP 解码器”

普通线性 GKP decoder 写成：

[
\hat e = K s+b.
]

这里 (s) 是测得的连续 GKP syndrome，(\hat e) 是估计的 data mode 位移误差。GKP-O2O 文献里通常把它写成一个 syndrome-informed displacement：

[
D[-f(s)],
]

其中 (f(s)) 是从 syndrome 估计 data 位移误差的函数。Brady 等人的综述明确说，O2O GKP 解码的关键就是从 ancilla stabilizer syndrome 推断 data 上的 additive noise，然后按某个估计函数施加 syndrome-informed displacement；他们把 **linear estimation** 和 **MMSE estimation** 作为两种主要解码策略。([arXiv][1])

你现在把它推广成：

[
\hat e
======

K_\theta s+b_\theta,
]

其中 (\theta) 表示当前噪声条件，例如 GKP squeezing、loss rate、dephasing rate、测量噪声、ancilla 噪声、空间相关噪声、时间漂移等。然后用 CNN 学习：

[
g_\phi:\theta_{\rm observed}\mapsto (K_\theta,b_\theta).
]

所以这不是一个固定 decoder，而是一个 **adaptive affine decoder**。如果用机器学习语言，它也很像 **hypernetwork**：一个网络生成另一个模型的权重。HyperNetworks 论文中，超网络的定义正是用一个网络生成另一个网络的权重；你的 CNN 输出 (K,b)，而 (K,b) 定义了后面的线性 decoder。([arXiv][2])

## 2. 为什么噪声变化会导致 (K,b) 变化？

在忽略 GKP modulo 折叠的局部高斯近似下，syndrome 与真实误差可以写成联合高斯变量：

[
\begin{pmatrix}
e\
s
\end{pmatrix}
\sim
\mathcal N
\left[
\begin{pmatrix}
\mu_e\
\mu_s
\end{pmatrix},
\begin{pmatrix}
\Sigma_{ee} & \Sigma_{es}\
\Sigma_{se} & \Sigma_{ss}
\end{pmatrix}
\right].
]

给定 (s)，最优线性最小均方估计器是：

[
\hat e
======

\mu_e+\Sigma_{es}\Sigma_{ss}^{-1}(s-\mu_s).
]

所以

[
K=\Sigma_{es}\Sigma_{ss}^{-1},
]

[
b=\mu_e-K\mu_s.
]

关键点是：(\Sigma_{es},\Sigma_{ss},\mu_e,\mu_s) 都会随噪声参数变化。比如测量噪声变大时，(\Sigma_{ss}) 变大，(K) 会变小；这表示 decoder 不应过度相信 syndrome。data–ancilla 噪声相关性变强时，(\Sigma_{es}) 变大，(K) 会更积极地利用 syndrome。Brady 等综述中也指出，Gaussian 解码步骤会让 data 与 ancilla 的 additive noises 相关，随后从 GKP-assisted homodyne syndrome 中估计 data noise；linear estimator 正是在忽略 GKP lattice modularity 的小噪声极限下得到的。([arXiv][1])

因此 CNN 学到的不是“量子纠错魔法”，而是近似学习这个映射：

[
\theta
\mapsto
\left(
\Sigma_{es}(\theta)\Sigma_{ss}(\theta)^{-1},
;
\mu_e(\theta)-K_\theta\mu_s(\theta)
\right).
]

## 3. CNN 在这里到底学什么？

假设你有一段 syndrome history 或 calibration map：

[
X =
{s_{t-L},\ldots,s_t,\text{测量强度},\text{squeezing},\text{loss proxy},\text{ancilla quality},\ldots}.
]

CNN 输出：

[
(K,b)=g_\phi(X).
]

然后 decoder 输出：

[
\hat e = K s_t+b.
]

这可以分成两层理解。

第一层，CNN 是 **噪声识别器**。它从 syndrome 图样中判断当前噪声是否更强、更弱、是否有空间相关、是否有测量偏置、是否有局部热点。surface-GKP 和 surface-code syndrome 都天然是二维或三维时空格点数据，所以 CNN 很适合提取局部模式。Wang 等人在 surface-GKP 码中引入神经网络 decoder，并明确说使用卷积操作解码连续变量系统下的 surface-GKP code；他们报告在一种设置下阈值从 MWPM 的约 (0.50) 提高到约 (0.78)，并指出模型可适应多种 error model，甚至可针对具体硬件样本定制。([Nature][3])

第二层，CNN 是 **参数生成器**。它不是直接输出 logical correction，而是输出当前最适合的 (K,b)。这种结构的好处是保留了物理可解释性：最终恢复仍然是 syndrome-informed displacement，而 CNN 只负责调节估计器的增益和偏置。

## 4. 与 MMSE GKP 解码的关系

完整的 GKP 解码不是单一线性函数，因为 syndrome 有 modulo lattice 结构：

[
s = H e+\eta \pmod{\Lambda}.
]

同一个 syndrome 可能对应多个 lattice branch：

[
e \sim s+\lambda_m,\qquad \lambda_m\in\Lambda.
]

真实后验分布通常是多个高斯分量的混合：

[
p(e\mid s,\theta)
=================

\sum_m w_m(s,\theta),
\mathcal N!\left(e;\mu_m(s,\theta),\Sigma_m(\theta)\right).
]

每个局部分支内，均值常常近似是仿射的：

[
\mu_m(s,\theta)=K_m(\theta)s+b_m(\theta).
]

所以 MMSE estimator 是：

[
f_{\rm MMSE}(s,\theta)
======================

# \mathbb E[e\mid s,\theta]

\sum_m w_m(s,\theta)
\left[
K_m(\theta)s+b_m(\theta)
\right].
]

Wu、Brady、Zhuang 的 O2O GKP 工作推导了 MMSE estimator，并指出它在最小化 residual noise 方面优于 linear estimator；综述也总结说 MMSE 比 linear estimation 更强，因为真实 joint PDF 不是单个 Gaussian，而是 Gaussian sum。([Quantum][4])

所以你的 CNN-(K,b) 方法可以看成对 MMSE 的一种低复杂度近似：

* 若 CNN 输出一个全局 (K,b)，它近似的是条件 LMMSE；
* 若 CNN 根据 syndrome 区域输出不同 (K,b)，它近似的是 piecewise-linear MMSE；
* 若 CNN 输出多组 ((K_m,b_m,w_m))，它就更接近 mixture-of-affine MMSE。

## 5. 为什么“近似 GKP 码”特别适合这种自适应方法？

理想 GKP 态是无限能量、不可归一化的；实际实验用的是有限能量近似 GKP 态。有限能量会带来两个重要影响：

1. 码字不再是完美 stabilizer eigenstate；
2. 噪声不再只是简单的独立高斯 displacement，而可能出现均值漂移、协方差变化、非高斯尾部、有限能量泄漏等效应。

Seshadreesan 等人把有限能量 GKP graph state 精确描述成“随机位移的理想 GKP graph state 的 Gaussian ensemble”，并指出协方差矩阵刻画有限能量近似带来的噪声，均值位移向量则与 homodyne 测量条件下可能产生的绝对位移误差相关。([arXiv][5])

这正好解释了你说的“噪声变化带来的参数偏移”：有限能量、loss、dephasing、homodyne 噪声会让

[
\mu_e,\mu_s,\Sigma_{es},\Sigma_{ss}
]

发生漂移，于是最优 (K,b) 也发生漂移。Jafarzadeh 等人在 2025 年关于 approximate GKP logical channels 的工作中也强调，有限能量码态会泄漏出理想 GKP code space，standard binning 对有限能量 GKP 通常不是最优；更好的 decoder 应该根据有效 squeezing / circuit noise 进行 tailoring。([arXiv][6])

因此，CNN 输出 (K,b) 的想法在近似 GKP 场景下尤其自然：它是在学习有限能量和实验噪声导致的 **effective channel drift**。

## 6. 训练目标应该怎么设计？

最直接的 supervised 训练是：

[
\min_\phi
\mathbb E
\left[
\left|
e-
\left(K_\phi(X)s+b_\phi(X)\right)
\right|^2
\right].
]

其中 (e) 是模拟器或实验标定中可得的真实位移误差标签。若噪声协方差已知，建议用 Mahalanobis loss：

[
\mathcal L_{\rm disp}
=====================

\mathbb E
\left[
(e-\hat e)^T
\Sigma_{\rm out}^{-1}
(e-\hat e)
\right].
]

但对 GKP 来说，普通 MSE 不够，因为误差有 lattice 等价关系。更合理的是 lattice-aware loss：

[
\mathcal L_{\rm GKP}
====================

\mathbb E
\left[
\min_{\lambda\in\Lambda_{\rm trivial}}
\left|
e-\hat e+\lambda
\right|^2
\right],
]

其中 (\Lambda_{\rm trivial}) 是不改变 logical Pauli frame 的稳定子位移格。这样 decoder 不会因为选择了等价的 stabilizer 位移而被错误惩罚。

如果目标是最终 logical correction，而不是物理 displacement，可以加一个 logical loss：

[
\mathcal L
==========

\mathcal L_{\rm disp}
+
\alpha,\mathcal L_{\rm logical}.
]

(\mathcal L_{\rm logical}) 可以是 logical class 的交叉熵，也可以是 Monte Carlo 估计的 logical failure rate surrogate。神经网络 decoder 在 QEC 中常被用来从 syndrome 直接学习 correction；例如 surface-code 领域已有 CNN、ANN、transformer/recurrent decoder，它们从结构化 syndrome 或硬件数据中学习纠错映射。([Quantum][7])

## 7. CNN 输出 (K,b) 的几种架构

### 架构 A：全局 (K,b)

[
(K,b)=g_\phi(X),
\qquad
\hat e=Ks+b.
]

适合小规模多模 GKP 或 O2O GKP。缺点是 (K) 维度可能很大，参数量为 (O(n^2))。

### 架构 B：局部卷积 (K_i,b_i)

对每个格点或每个 mode 输出局部修正：

[
\hat e_i
========

\sum_{j\in\mathcal N(i)}
K_{ij}(X)s_j+b_i(X).
]

这更像 surface-GKP：误差相关性通常局域，CNN 的局部 receptive field 很自然。它还能避免输出巨大 dense matrix。

### 架构 C：低秩/基展开

令

[
K(X)
====

K_0+\sum_{\ell=1}^r \alpha_\ell(X)B_\ell,
]

[
b(X)
====

b_0+\sum_{\ell=1}^r \beta_\ell(X)c_\ell.
]

CNN 只输出 (\alpha_\ell,\beta_\ell)，而 (B_\ell,c_\ell) 是预定义或可学习的物理基。这个版本最稳，因为它把 CNN 的自由度限制在“调节噪声参数”上，而不是任意生成一个可能不稳定的矩阵。

### 架构 D：mixture-of-affine decoder

[
\hat e
======

\sum_m
\pi_m(X,s)
\left[
K_m(X)s+b_m(X)
\right].
]

这是最接近 GKP MMSE 的版本，因为 GKP 后验本来就是多 lattice branch 的高斯混合。若只用一个 (K,b)，跨越 modulo 边界时性能会明显下降；mixture 结构可以缓解这个问题。

---

## 8. 它为什么能“近似 GKP 解码”？

完整 GKP 最大似然 / MMSE 解码需要处理：

[
p(e\mid s,\theta)
]

这个复杂后验。CNN-(K,b) 方法把这个问题分解成两步：

第一步，CNN 从 syndrome pattern 和噪声上下文中估计当前 posterior 的形状：

[
X\mapsto \text{effective } \mu,\Sigma,\text{branch reliability}.
]

第二步，用一个快速仿射估计器近似 posterior mean：

[
\hat e\approx \mathbb E[e\mid s,\theta].
]

所以它的本质是 **amortized Bayesian estimation**：训练阶段花大量模拟代价学习后验结构；实时解码阶段只需要一次 CNN 前向传播和一次矩阵乘法。

这与传统 ML decoder 的关系是：

[
\text{ML/MMSE 解码：每次重新解优化问题}
]

[
\text{CNN-}K,b\text{ 解码：训练时学会优化结果，推理时快速生成近似解}
]

这就是它可能适合实时 GKP 反馈的原因。

---

## 9. 关键风险：单个 (K,b) 不能表达 GKP 的周期非线性

这个方案最容易出错的地方是：GKP syndrome 是 modulo 的。单个全局仿射函数

[
\hat e=Ks+b
]

不能同时处理所有 lattice branch。比如一维 square GKP 中，syndrome (s\approx 0) 很可靠；但 (s\approx \sqrt{\pi}/2) 附近接近判决边界，后验可能是双峰的。此时一个线性估计器会把两个可能分支平均，导致估计落在物理上不太合理的位置。

所以如果你用 CNN 生成单个 (K,b)，最好满足以下条件：

* 噪声较小；
* syndrome 多数时间远离 modulo 边界；
* finite squeezing 足够好；
* 只追求 residual displacement noise 降低，而不是完全 ML logical decoding。

如果希望更接近真正 GKP 解码，建议用：

[
{K_m,b_m,\pi_m}_{m=1}^M
=======================

g_\phi(X,s),
]

再输出

[
\hat e
======

\sum_m
\pi_m(K_m s+b_m).
]

这会把 GKP 的“多个候选格点分支”显式放进模型里。

## 10. 一个合理的完整流程

可以这样设计：

1. **生成训练数据**
   随机采样噪声参数 (\theta)：squeezing、loss、dephasing、测量噪声、ancilla 噪声、空间相关长度等。

2. **模拟近似 GKP syndrome**
   得到连续 syndrome (s)、历史 syndrome tensor (X)、真实 displacement error (e)、以及最终 logical class。

3. **CNN 输出 decoder 参数**
   [
   (K,b)=g_\phi(X).
   ]

4. **仿射估计 displacement**
   [
   \hat e=Ks+b.
   ]

5. **施加 correction 或更新 Pauli frame**
   实际操作是施加 (-\hat e)，或者在软件中更新 displacement / Pauli frame。

6. **用 lattice-aware loss 训练**
   同时优化 residual displacement 与 logical failure。

7. **在线部署**
   实验中实时输入最近若干轮 syndrome，CNN 自适应输出 (K,b)，从而跟踪噪声漂移。

## 11. 最重要的物理解释

你的方案的物理图像是：

> 近似 GKP 码在真实硬件中并不面对固定高斯噪声，而是面对随时间、空间、测量历史、有限能量效应变化的有效噪声通道。
> 对每一个局部噪声通道，都存在一个近似最优的线性 syndrome-informed displacement。
> CNN 的作用是从 syndrome 图样中估计当前有效通道，并生成对应的 (K,b)。

所以它不是替代理论 GKP 解码，而是把理论中的

[
K(\theta)=\Sigma_{es}(\theta)\Sigma_{ss}(\theta)^{-1}
]

变成一个可学习、可实时更新的模型：

[
K(\theta),b(\theta)
\approx
g_\phi(X).
]

这在近似 GKP 场景中尤其有意义，因为有限能量 GKP 态的噪声可表现为协方差和均值位移的动态变化，而这些正是 (K,b) 最敏感的量。([arXiv][5])

如果你要真正实现这个方案，不要让 CNN 直接输出一个完全自由的 dense (K)。更稳的做法是：

[
K = K_0+\Delta K_\phi(X),
\qquad
b=b_0+\Delta b_\phi(X),
]

其中 (K_0,b_0) 来自解析 LMMSE 或标定噪声模型，CNN 只学习偏移量。这样模型既保留 GKP 线性解码的物理结构，又能适应有限能量、非平稳噪声和硬件漂移。

更进一步，可以使用 mixture-of-affine decoder：

[
\hat e
======

\sum_m
\pi_m(X,s)
\left[
(K_0+\Delta K_m(X))s
+
(b_0+\Delta b_m(X))
\right],
]

这比单个 (K@s+b) 更符合 GKP 的 modulo lattice 本质，也更接近 MMSE 解码。

## 1. 你的方案的理论定位：自适应 LMMSE / amortized linear decoder

在局部高斯近似下，GKP syndrome 和真实位移误差满足近似联合高斯模型。固定噪声参数 (\theta) 时，最优线性估计器是：

[
K^*(\theta)=\Sigma_{es}(\theta)\Sigma_{ss}(\theta)^{-1},
\qquad
b^*(\theta)=\mu_e(\theta)-K^*(\theta)\mu_s(\theta).
]

\hat e=K(\theta)s+b(\theta),\qquad K^*(\theta)=\Sigma_{es}(\theta)\Sigma_{ss}(\theta)^{-1}

所以你的 CNN 本质上是在学习：

[
X_{t-L:t}\mapsto \theta_t\mapsto K^*(\theta_t),b^*(\theta_t).
]

这不是“黑盒替代 GKP 解码”，而是**用神经网络在线逼近当前噪声条件下的最佳线性 GKP 估计器**。这和 GKP oscillator-to-oscillator 文献中的 linear estimation / MMSE estimation 是一致的：Wu、Brady、Zhuang 推导了 GKP-stabilizer code 的 MMSE 估计器，并明确指出 MMSE 优于 linear estimator；其线性估计器可看成只保留一个局部高斯分支的近似。([Quantum][1])

## 2. 为什么慢 CNN + 快 FPGA 很合理？

量子纠错解码有两个很不同的时间尺度：

**快时间尺度**：每一轮 syndrome 到来后必须低延迟处理。实时 QEC 文献反复强调，吞吐量和闭环延迟是关键指标；已有 FPGA-based NN surface-code decoder 的实验报告给出了 550 ns 确定闭环延迟，其中 NN 解码为 124 ns，用于 1.25 μs QEC cycle 内的反馈。([arXiv][2])

**慢时间尺度**：噪声场、GKP squeezing、测量偏置、ancilla 质量、loss、串扰、温漂通常不会每个 cycle 大幅随机变化，而是缓慢漂移或分段变化。因此让 CNN 在慢回路中估计 (K,b)，再让 FPGA 在快回路中执行矩阵乘加，是非常合理的两时间尺度分解。

这也和 GKP 文献中的“实时软信息”思想吻合。Noh、Chamberland、Brandão 的 surface-GKP 方案中，matching graph 的边权会根据 GKP analog information 和 syndrome 历史动态计算；他们指出这种动态利用 syndrome 历史是低逻辑失败率的重要来源。([arXiv][3]) 2025 年 QLDPC-GKP circuit-level soft-information 工作也比较了无软信息、预计算可靠度、实时软信息三种情况，结论是只有实时软信息场景带来显著 frame error rate 改善。([arXiv][4])

你的方案可以看成：**把“实时软信息”进一步压缩成 FPGA 友好的 (K,b)**。

## 3. 混合仿射解码会不会不方便 FPGA？

是的，**完整混合仿射解码通常更不方便 FPGA 部署**，尤其如果它需要实时计算多个分支权重：

[
\hat e
======

\sum_{m=1}^{M}
\pi_m(s,X)
\left(K_m s+b_m\right).
]

它比单一 (K s+b) 多了三类开销：

1. 多组矩阵乘法：(M) 个 (K_m s)；
2. 分支权重计算：(\pi_m(s,X))，可能涉及 softmax、指数、归一化；
3. 分支选择或加权平均：增加 DSP、BRAM、routing 和定点误差管理成本。

但它**不是完全不可部署**。可以有三个折中版本：

| 方案                    | FPGA 复杂度 | 表达能力 | 适合场景                      |
| --------------------- | -------: | ---: | ------------------------- |
| 单一 (K,b)              |       最低 |   中等 | 小噪声、单一分支占优、强实时约束          |
| 分段仿射 LUT              |      低到中 |   较高 | syndrome 边界附近错误重要         |
| Top-2 / Top-4 mixture |      中到高 |    高 | modulo 分支竞争明显             |
| 完整 mixture + softmax  |        高 |   最高 | 更适合 GPU/CPU 或离线 benchmark |

对 FPGA 来说，我不建议一开始采用完整 mixture。更好的路径是：**保留你的单一 (K,b) 快回路，把 mixture-of-affine 作为离线 upper baseline 或后续增强版本**。如果发现性能瓶颈主要来自 GKP modulo 边界附近，再考虑加入少量分支，例如 Top-2 分段仿射，而不是直接上完整 mixture。

## 4. 当前设计是否合理？结论：合理，但适用条件要讲清楚

你的方法合理的条件是：

第一，噪声漂移相对慢。CNN 的更新周期必须快于噪声统计量明显变化的时间尺度。若 (K,b) 更新延迟太大，快回路会使用过期参数。

第二，真实后验在大多数时候接近单分支高斯。也就是说 syndrome 多数时候不在 GKP modulo 判决边界附近。若大量样本落在边界附近，单一 (K,b) 会把多峰后验“平均掉”，这时 mixture 或最近格点/MMSE 会更优。

第三，CNN 输入确实包含足够信息来识别噪声场。输入只用当前 (s_t) 可能不够；最好用 syndrome history、局部空间 patch、测量幅度、GKP ancilla 指标、校准结果、温漂/损耗 proxy 等。

第四，FPGA 定点量化不会破坏 (K,b) 的稳定性。你需要单独评估 8/10/12/16-bit 定点下的 logical failure rate，而不能只看浮点仿真。

在这些条件下，你的架构很有优势：**它保留了 GKP 线性估计的物理结构，同时引入了对非平稳复杂噪声的自适应能力**。

## 5. 与其它解码方法相比，理论上能不能更优秀？

要分清“比谁优秀”。

### 能超过的对象

你的方法理论上很可能超过：

1. **固定 (K_0,b_0) 线性解码器**
   因为固定参数只适合 nominal noise；噪声漂移后，最优 (K^*,b^*) 改变，而 CNN 可以跟踪。

2. **closest-integer / hard GKP decoder**
   这种方法只利用 syndrome 的最近格点信息，不充分利用连续可靠度。GKP 和 GKP-concatenated 文献已经反复显示 analog / soft information 能显著提升性能。Raveendran 等人在 QLDPC-GKP 中展示，内层 GKP analog information 能提升外层 iterative decoder 阈值并降低 error floor。([Quantum][5])

3. **假设错误噪声模型的 MWPM / min-sum / BP**
   如果真实噪声存在空间相关、时间相关、偏置、非平稳漂移，固定边权或固定信道模型的 decoder 会失配。神经网络 decoder 在 surface-code 实验数据中能优于 MWPM，部分原因就是更好处理相关 syndrome 缺陷；Varbanov 等报告 NN decoder 在 Google Quantum AI 实验数据上 logical error rate 约比 MWPM 低 25%，并且使用 analog soft information 还能进一步降低逻辑错误率。([TU Delft Research Portal][6])

### 通常不能超过的对象

你的方法通常不能超过：

1. **已知真实噪声模型下的 oracle MMSE / ML decoder**
   如果对方知道完整真实后验 (p(e|s,\theta))，并且不受实时硬件限制，那它是 Bayes-optimal 或接近 Bayes-optimal。你的 (K,b) 是低复杂度近似。

2. **小规模精确 lattice theta / CVP / closest-point decoder**
   对小系统、离线仿真、可承受高复杂度时，精确或高精度近似的 GKP maximum-likelihood decoder 通常是更强 baseline。GKP lattice perspective 文献指出，GKP 最大似然解码可以用 lattice theta function 描述。([Quantum][7])

3. **完整 MMSE GKP decoder**
   Wu、Brady、Zhuang 的数值结果显示，MMSE 的 break-even point 可优于 square-lattice linear estimation；他们报告 single-layer codes using MMSE 的 break-even point 约为 (\sigma^*_{\rm MMSE}\approx0.605(5))，而 square lattice linear estimation 约为 (\sigma^*_{\rm lin}\approx0.558)。([Quantum][1])

所以最准确的说法是：

> 你的方法理论上可以优于固定模型、硬判决、静态线性和失配的传统 decoder；但不应声称能超过已知真实信道的 oracle MMSE / ML。它的核心优势是 **性能-延迟-可部署性折中**。

## 6. 一个有用的理论判据：预测 (K,b) 的误差如何影响性能

把偏置并入增广 syndrome：

[
\bar s=
\begin{bmatrix}
s\
1
\end{bmatrix},
\qquad
W=
\begin{bmatrix}
K & b
\end{bmatrix}.
]

则

[
\hat e = W\bar s.
]

对固定噪声条件 (\theta)，最优线性解码器是 (W^*(\theta))。如果你的 CNN 输出 (\hat W)，则在线性高斯假设下，额外 MSE 近似为：

[
\Delta{\rm MSE}
===============

{\rm Tr}
\left[
(\hat W-W^*)
,
\mathbb E[\bar s\bar s^T]
,
(\hat W-W^*)^T
\right].
]

\Delta\mathrm{MSE}=\mathrm{Tr}!\left[(\hat W-W^*),\mathbb E[\bar s\bar s^T],(\hat W-W^*)^T\right]

这给了你一个很清楚的理论目标：CNN 不一定要完美识别噪声参数 (\theta)，它只需要让 (\hat W) 比固定 (W_0) 更接近当前 (W^*(\theta))。如果做到这一点，你就能严格地降低线性估计族内的 MSE。

## 7. baseline 应该怎么设置？

我建议把 baseline 分成四层，否则审稿或答辩时容易被质疑“不公平”。

### A. GKP 内层解码 baseline

| Baseline                                        | 目的                       |
| ----------------------------------------------- | ------------------------ |
| No correction / no adaptive correction          | sanity check             |
| Closest-integer GKP decoder                     | 最基础硬判决                   |
| Static analytic linear decoder (K_0,b_0)        | 证明 adaptive 有用           |
| Static trained linear decoder                   | 排除“只是训练更好”的因素            |
| Oracle linear decoder (K^*(\theta),b^*(\theta)) | 线性族上界                    |
| Bayesian / MMSE decoder，小规模可算                   | 近似理论上界                   |
| Nearest-lattice / closest-point decoder         | GKP lattice 解码强 baseline |

其中 **oracle linear decoder** 很关键。它回答的问题是：你的 CNN 是否真的学到了接近当前最优线性解码器的参数。如果你的 CNN 和 oracle linear 差距很小，就说明慢回路预测是成功的。

### B. 自适应方法 baseline

| Baseline                                  | 目的                 |
| ----------------------------------------- | ------------------ |
| 滑动窗口估计协方差 + LMMSE                         | 传统统计自适应            |
| Kalman / recursive least squares 更新 (K,b) | 对比 CNN 是否必要        |
| 噪声参数分桶 + LUT (K,b)                        | 对比 CNN 是否优于查表      |
| MLP 输出 (K,b)                              | 证明 CNN 的空间局部归纳偏置有用 |
| CNN 直接输出 (\hat e)                         | 对比“物理结构约束”是否有优势    |
| CNN 输出 (\Delta K,\Delta b) vs 直接输出 (K,b)  | 验证残差学习稳定性          |

我特别建议加入：

[
K=K_0+\Delta K_\phi(X),\qquad b=b_0+\Delta b_\phi(X)
]

这个版本。它通常比直接预测完整 (K,b) 更稳，也更容易解释。

### C. 外层码 baseline，如果你有 surface-GKP / QLDPC-GKP

| Baseline                                               | 目的                    |
| ------------------------------------------------------ | --------------------- |
| hard MWPM / hard min-sum                               | 不用 analog information |
| soft MWPM / soft min-sum，静态边权                          | 使用固定 soft info        |
| dynamic soft MWPM / real-time soft info                | 当前强 baseline          |
| 你的 CNN-(K,b)+FPGA linear inner decoder + outer decoder | 完整方案                  |
| oracle soft-information outer decoder                  | 上界                    |

surface-GKP 文献中，MWPM、动态边权、analog information 都是自然 baseline。Wang 等的 surface-GKP CNN decoder 报告在连续变量系统下使用卷积神经网络解码，并给出比 MWPM 更高的阈值结果，可作为 NN 类 baseline 参考。([Nature][8])

### D. 硬件 baseline

## 8. 实验场景应该怎么设计？

至少需要这几类噪声场景：

1. **stationary Gaussian displacement**
   证明你的方法不会比标准 LMMSE 差太多。

2. **缓慢漂移噪声**
   例如 squeezing、loss、measurement variance 随时间漂移。这里你的方法应该明显优于 fixed (K,b)。

3. **空间非均匀噪声场**
   某些 mode 或 lattice patch 噪声更强。CNN 的局部卷积结构应该有优势。

4. **时间相关噪声**
   例如 (1/f) noise、burst noise、Markov switching noise。测试慢回路能否跟踪。

5. **模型失配噪声**
   训练在 Gaussian + drift，测试在轻微非高斯尾部、偏置、相关噪声。证明泛化。

6. **GKP modulo 边界压力测试**
   专门统计 syndrome 接近 (\pm\sqrt{\pi}/2) 的样本性能。这能判断是否需要 mixture-of-affine。

## 9. 如何判断是否需要混合仿射？

你可以做一个很直接的 ablation：

1. 当前单一 (K,b)：
   [
   \hat e=Ks+b.
   ]

2. Top-2 piecewise affine：
   [
   \hat e =
   \begin{cases}
   K_1s+b_1,& s\in \mathcal R_1,\
   K_2s+b_2,& s\in \mathcal R_2.
   \end{cases}
   ]

3. 离线完整 mixture-of-affine：
   [
   \hat e=\sum_m \pi_m(K_ms+b_m).
   ]

如果 2 或 3 只在极少数边界样本上提升，而总体 logical error rate 改善很小，就不要牺牲 FPGA 简洁性。如果 mixture 在目标噪声区间显著降低 logical failure rate，才考虑硬件化一个简化版，比如 LUT 分支选择 + 两组 (K,b)。

我的建议是：**先不要换掉你现在的架构。把 mixture 作为离线 upper bound，确认性能瓶颈后再决定是否硬件化。**

## 1. 你的方案的理论定位：自适应 LMMSE / amortized linear decoder

在局部高斯近似下，GKP syndrome 和真实位移误差满足近似联合高斯模型。固定噪声参数 (\theta) 时，最优线性估计器是：

[
K^*(\theta)=\Sigma_{es}(\theta)\Sigma_{ss}(\theta)^{-1},
\qquad
b^*(\theta)=\mu_e(\theta)-K^*(\theta)\mu_s(\theta).
]

\hat e=K(\theta)s+b(\theta),\qquad K^*(\theta)=\Sigma_{es}(\theta)\Sigma_{ss}(\theta)^{-1}

所以你的 CNN 本质上是在学习：

[
X_{t-L:t}\mapsto \theta_t\mapsto K^*(\theta_t),b^*(\theta_t).
]

这不是“黑盒替代 GKP 解码”，而是**用神经网络在线逼近当前噪声条件下的最佳线性 GKP 估计器**。这和 GKP oscillator-to-oscillator 文献中的 linear estimation / MMSE estimation 是一致的：Wu、Brady、Zhuang 推导了 GKP-stabilizer code 的 MMSE 估计器，并明确指出 MMSE 优于 linear estimator；其线性估计器可看成只保留一个局部高斯分支的近似。([Quantum][1])

## 2. 为什么慢 CNN + 快 FPGA 很合理？

量子纠错解码有两个很不同的时间尺度：

**快时间尺度**：每一轮 syndrome 到来后必须低延迟处理。实时 QEC 文献反复强调，吞吐量和闭环延迟是关键指标；已有 FPGA-based NN surface-code decoder 的实验报告给出了 550 ns 确定闭环延迟，其中 NN 解码为 124 ns，用于 1.25 μs QEC cycle 内的反馈。([arXiv][2])

**慢时间尺度**：噪声场、GKP squeezing、测量偏置、ancilla 质量、loss、串扰、温漂通常不会每个 cycle 大幅随机变化，而是缓慢漂移或分段变化。因此让 CNN 在慢回路中估计 (K,b)，再让 FPGA 在快回路中执行矩阵乘加，是非常合理的两时间尺度分解。

这也和 GKP 文献中的“实时软信息”思想吻合。Noh、Chamberland、Brandão 的 surface-GKP 方案中，matching graph 的边权会根据 GKP analog information 和 syndrome 历史动态计算；他们指出这种动态利用 syndrome 历史是低逻辑失败率的重要来源。([arXiv][3]) 2025 年 QLDPC-GKP circuit-level soft-information 工作也比较了无软信息、预计算可靠度、实时软信息三种情况，结论是只有实时软信息场景带来显著 frame error rate 改善。([arXiv][4])

你的方案可以看成：**把“实时软信息”进一步压缩成 FPGA 友好的 (K,b)**。

## 3. 混合仿射解码会不会不方便 FPGA？

是的，**完整混合仿射解码通常更不方便 FPGA 部署**，尤其如果它需要实时计算多个分支权重：

[
\hat e
======

\sum_{m=1}^{M}
\pi_m(s,X)
\left(K_m s+b_m\right).
]

它比单一 (K s+b) 多了三类开销：

1. 多组矩阵乘法：(M) 个 (K_m s)；
2. 分支权重计算：(\pi_m(s,X))，可能涉及 softmax、指数、归一化；
3. 分支选择或加权平均：增加 DSP、BRAM、routing 和定点误差管理成本。

但它**不是完全不可部署**。可以有三个折中版本：

| 方案                    | FPGA 复杂度 | 表达能力 | 适合场景                      |
| --------------------- | -------: | ---: | ------------------------- |
| 单一 (K,b)              |       最低 |   中等 | 小噪声、单一分支占优、强实时约束          |
| 分段仿射 LUT              |      低到中 |   较高 | syndrome 边界附近错误重要         |
| Top-2 / Top-4 mixture |      中到高 |    高 | modulo 分支竞争明显             |
| 完整 mixture + softmax  |        高 |   最高 | 更适合 GPU/CPU 或离线 benchmark |

对 FPGA 来说，我不建议一开始采用完整 mixture。更好的路径是：**保留你的单一 (K,b) 快回路，把 mixture-of-affine 作为离线 upper baseline 或后续增强版本**。如果发现性能瓶颈主要来自 GKP modulo 边界附近，再考虑加入少量分支，例如 Top-2 分段仿射，而不是直接上完整 mixture。

## 4. 当前设计是否合理？结论：合理，但适用条件要讲清楚

你的方法合理的条件是：

第一，噪声漂移相对慢。CNN 的更新周期必须快于噪声统计量明显变化的时间尺度。若 (K,b) 更新延迟太大，快回路会使用过期参数。

第二，真实后验在大多数时候接近单分支高斯。也就是说 syndrome 多数时候不在 GKP modulo 判决边界附近。若大量样本落在边界附近，单一 (K,b) 会把多峰后验“平均掉”，这时 mixture 或最近格点/MMSE 会更优。

第三，CNN 输入确实包含足够信息来识别噪声场。输入只用当前 (s_t) 可能不够；最好用 syndrome history、局部空间 patch、测量幅度、GKP ancilla 指标、校准结果、温漂/损耗 proxy 等。

第四，FPGA 定点量化不会破坏 (K,b) 的稳定性。你需要单独评估 8/10/12/16-bit 定点下的 logical failure rate，而不能只看浮点仿真。

在这些条件下，你的架构很有优势：**它保留了 GKP 线性估计的物理结构，同时引入了对非平稳复杂噪声的自适应能力**。

## 5. 与其它解码方法相比，理论上能不能更优秀？

要分清“比谁优秀”。

### 能超过的对象

你的方法理论上很可能超过：

1. **固定 (K_0,b_0) 线性解码器**
   因为固定参数只适合 nominal noise；噪声漂移后，最优 (K^*,b^*) 改变，而 CNN 可以跟踪。

2. **closest-integer / hard GKP decoder**
   这种方法只利用 syndrome 的最近格点信息，不充分利用连续可靠度。GKP 和 GKP-concatenated 文献已经反复显示 analog / soft information 能显著提升性能。Raveendran 等人在 QLDPC-GKP 中展示，内层 GKP analog information 能提升外层 iterative decoder 阈值并降低 error floor。([Quantum][5])

3. **假设错误噪声模型的 MWPM / min-sum / BP**
   如果真实噪声存在空间相关、时间相关、偏置、非平稳漂移，固定边权或固定信道模型的 decoder 会失配。神经网络 decoder 在 surface-code 实验数据中能优于 MWPM，部分原因就是更好处理相关 syndrome 缺陷；Varbanov 等报告 NN decoder 在 Google Quantum AI 实验数据上 logical error rate 约比 MWPM 低 25%，并且使用 analog soft information 还能进一步降低逻辑错误率。([TU Delft Research Portal][6])

### 通常不能超过的对象

你的方法通常不能超过：

1. **已知真实噪声模型下的 oracle MMSE / ML decoder**
   如果对方知道完整真实后验 (p(e|s,\theta))，并且不受实时硬件限制，那它是 Bayes-optimal 或接近 Bayes-optimal。你的 (K,b) 是低复杂度近似。

2. **小规模精确 lattice theta / CVP / closest-point decoder**
   对小系统、离线仿真、可承受高复杂度时，精确或高精度近似的 GKP maximum-likelihood decoder 通常是更强 baseline。GKP lattice perspective 文献指出，GKP 最大似然解码可以用 lattice theta function 描述。([Quantum][7])

3. **完整 MMSE GKP decoder**
   Wu、Brady、Zhuang 的数值结果显示，MMSE 的 break-even point 可优于 square-lattice linear estimation；他们报告 single-layer codes using MMSE 的 break-even point 约为 (\sigma^*_{\rm MMSE}\approx0.605(5))，而 square lattice linear estimation 约为 (\sigma^*_{\rm lin}\approx0.558)。([Quantum][1])

所以最准确的说法是：

> 你的方法理论上可以优于固定模型、硬判决、静态线性和失配的传统 decoder；但不应声称能超过已知真实信道的 oracle MMSE / ML。它的核心优势是 **性能-延迟-可部署性折中**。

## 6. 一个有用的理论判据：预测 (K,b) 的误差如何影响性能

把偏置并入增广 syndrome：

[
\bar s=
\begin{bmatrix}
s\
1
\end{bmatrix},
\qquad
W=
\begin{bmatrix}
K & b
\end{bmatrix}.
]

则

[
\hat e = W\bar s.
]

对固定噪声条件 (\theta)，最优线性解码器是 (W^*(\theta))。如果你的 CNN 输出 (\hat W)，则在线性高斯假设下，额外 MSE 近似为：

[
\Delta{\rm MSE}
===============

{\rm Tr}
\left[
(\hat W-W^*)
,
\mathbb E[\bar s\bar s^T]
,
(\hat W-W^*)^T
\right].
]

\Delta\mathrm{MSE}=\mathrm{Tr}!\left[(\hat W-W^*),\mathbb E[\bar s\bar s^T],(\hat W-W^*)^T\right]

这给了你一个很清楚的理论目标：CNN 不一定要完美识别噪声参数 (\theta)，它只需要让 (\hat W) 比固定 (W_0) 更接近当前 (W^*(\theta))。如果做到这一点，你就能严格地降低线性估计族内的 MSE。

是否可以拿这套CNN+FPGA方法去和MWPM方法或者其它解码方法进行比较？

可以，而且**应该比较**。但要注意：你的 CNN+FPGA 方法和 MWPM 不一定处在同一层级。最公平的做法是把比较分成两类：

1. **算法性能比较**：逻辑错误率、阈值、残余位移方差、frame error rate。
2. **系统实现比较**：延迟、吞吐、FPGA 资源、定点量化损失、参数更新带宽。

否则容易出现“不公平比较”：例如拿你的实时 FPGA 快回路去比离线 MWPM 的逻辑错误率，或者拿你的自适应 CNN 去比静态 MWPM 的固定边权。

---

## 1. 可以和 MWPM 比，但要明确 MWPM 在哪一层

如果你只做 **单模或多模 GKP 内层位移估计**：

[
\hat e = K s+b,
]

那么 MWPM 不是最自然的直接 baseline。此时更合适的 baseline 是：

| 任务          | 合理 baseline                                 |
| ----------- | ------------------------------------------- |
| GKP 内层位移估计  | nearest-integer / closest-point GKP decoder |
| GKP 内层软信息   | fixed linear estimator, MMSE estimator      |
| 多模 GKP 格码   | nearest-lattice / closest-vector decoder    |
| 近似 GKP 有限能量 | static (K,b), oracle (K^*,b^*), MMSE        |

MWPM 更适合用于 **surface code、toric code、surface-GKP、GKP-surface concatenation** 这类外层拓扑码解码。surface-GKP 文献中确实常用 MWPM 作为基线；例如 Wang 等人在 surface-GKP 中先用 MWPM 解 3D 时空图，然后又引入卷积神经网络 decoder，并报告 CNN threshold 高于 MWPM baseline。([Nature][1])

所以如果你的系统是：

[
\text{GKP 内层} + \text{surface/toric/QLDPC 外层},
]

那就非常适合和 MWPM 或 BP / min-sum / union-find 比较。

---

## 2. 最公平的 MWPM baseline 应该有多个版本

不要只设置一个“MWPM baseline”。建议至少设置以下四个：

| Baseline                 | 说明                             | 目的                       |
| ------------------------ | ------------------------------ | ------------------------ |
| **Hard MWPM**            | 只用离散 syndrome，不用 GKP analog 信息 | 最基础传统 baseline           |
| **Static-weight MWPM**   | 边权由固定 nominal 噪声模型给出           | 对比静态噪声假设                 |
| **Adaptive-weight MWPM** | 边权根据当前估计噪声更新                   | 对比你的 CNN 自适应优势是否来自“更新权重” |
| **Oracle-weight MWPM**   | 使用真实噪声参数或真实错误概率生成边权            | MWPM 类方法的近似上界            |

你的方法如果只和 Hard MWPM 比，容易被质疑 baseline 太弱。GKP 相关文献已经显示 analog/soft information 对外层解码很重要：QLDPC-GKP 工作表明，内层 GKP analog information 可以提高外层 iterative decoder 阈值，并降低或消除 error floor；2025 年 circuit-level QLDPC-GKP 工作也强调，内层 bosonic syndrome 的 analog information 会用于 informing 外层 stabilizer code 解码。([Quantum][2])

因此，真正有说服力的比较应该是：

[
\text{CNN-adaptive } K,b
\quad \text{vs.} \quad
\text{soft/adaptive MWPM}.
]

---

## 3. 你的方法和 MWPM 比的核心卖点不是“万能更准”，而是“自适应 + 低延迟”

MWPM 的优势是成熟、可解释、在图状独立错误模型下非常强。你的 CNN+FPGA 方法的优势是：

[
\text{复杂噪声场} \Rightarrow \text{CNN 估计漂移}
\Rightarrow K_t,b_t
\Rightarrow \text{FPGA 低延迟仿射解码}.
]

也就是说，你的强项是：

* 噪声非平稳；
* 存在空间非均匀噪声；
* 存在时间漂移；
* 存在测量偏置；
* 存在相关错误或模型失配；
* 需要严格实时闭环；
* 不希望在快回路中跑复杂图匹配或完整神经网络。

这和近年的 NN decoder 结果方向一致。Varbanov 等人在 surface-code 实验数据上报告，NN decoder 可以比 MWPM 取得更低逻辑错误率，原因之一是 NN 更能处理导致多个相关 syndrome defect 的错误；他们还报告，在 Google Quantum AI 实验数据上 NN 逻辑错误率约比 MWPM 低 25%，加入 analog soft information 又可进一步降低逻辑错误率。([TU Delft Research Portal][3])

但你不应该声称“理论上一定优于 MWPM”。更准确的说法是：

> 在非平稳、相关、带 analog syndrome 的复杂噪声场中，CNN-adaptive affine decoder 有机会优于静态 MWPM 或失配 MWPM；但在 MWPM 拿到 oracle 边权、错误模型正好图状独立、且无实时硬件限制时，MWPM 仍然可能非常强。

## 4. 推荐的完整比较矩阵

我建议你的实验表格这样设计：

| 类别               | 方法                                    |    是否自适应 | 是否用 analog info | 是否硬件友好 |
| ---------------- | ------------------------------------- | -------: | --------------: | -----: |
| GKP hard decoder | nearest-integer rounding              |        否 |               弱 |      是 |
| 固定线性             | fixed (K_0,b_0)                       |        否 |               是 |      是 |
| 统计自适应            | sliding-window LMMSE / RLS            |        是 |               是 |      中 |
| 你的方法             | CNN-predicted (K_t,b_t) + FPGA        |        是 |               是 |      是 |
| 外层传统             | hard MWPM                             |        否 |               否 |      中 |
| 外层 soft          | static weighted MWPM                  |        否 |               是 |      中 |
| 外层自适应            | adaptive weighted MWPM                |        是 |               是 |      中 |
| 强上界              | oracle-weight MWPM / oracle (K^*,b^*) | 是，oracle |               是 |    否或中 |
| 离线上界             | MMSE / ML / closest lattice           | 是，oracle |               是 |    通常否 |

最关键的 baseline 是这三个：

[
\text{fixed }K_0,b_0,
]

[
\text{adaptive weighted MWPM},
]

[
\text{oracle }K^*,b^*.
]

如果你的方法能接近 oracle (K^*,b^*)，并且在复杂漂移噪声下超过 fixed (K_0,b_0) 和 static weighted MWPM，那就说明你的慢回路 CNN 真的学到了噪声漂移。

## 5. 评价指标不要只看逻辑错误率

建议报告：

| 指标                                    | 为什么重要           |
| ------------------------------------- | --------------- |
| logical error rate / frame error rate | 主要纠错性能          |
| threshold 或 pseudo-threshold          | 展示可扩展趋势         |
| residual displacement variance        | 直接衡量 GKP 内层解码质量 |
| latency                               | 你的 FPGA 快回路核心优势 |
| throughput                            | 是否满足 QEC cycle  |
| FPGA LUT / FF / DSP / BRAM            | 可部署性            |
| 定点位宽敏感性                               | 证明不是浮点幻觉        |
| stale-(K,b) penalty                   | 慢回路更新延迟的影响      |
| train/test noise mismatch             | 证明泛化能力          |
| burst / drift / correlated noise 下性能  | 证明 CNN 的必要性     |

这点很重要，因为你的方法可能不是所有条件下逻辑错误率最高，但它可能在 **性能-延迟-资源** 三维折中上最好。实时 QEC 硬件论文已经把这种系统指标作为核心；例如 2026 年 FPGA-based NN surface-code 实验报告了 550 ns 确定闭环延迟，其中 NN 解码 124 ns，并能在 1.25 μs QEC cycle 内反馈。([arXiv][4])

## 6. 理论上什么时候你会赢？

你的 CNN+FPGA 方法最可能赢的场景是：

### 情况 A：噪声参数慢漂移

固定 MWPM 或 fixed (K,b) 使用过期信道模型。你的 CNN 根据 syndrome history 更新：

[
K_t,b_t.
]

这时你可以接近当前条件下的 oracle linear decoder。

### 情况 B：空间非均匀噪声

某些区域 squeezing 较差、loss 较大、测量偏置较强。CNN 可以从局部 syndrome pattern 中识别噪声热点，输出局部修正矩阵或局部 (K,b)。静态 MWPM 若仍用均匀边权，会吃亏。

### 情况 C：相关错误或非图状错误

MWPM 最适合图状匹配问题；如果错误导致多个相关 syndrome defects，NN 类方法可能更容易学习这些相关结构。surface-code NN decoder 文献中就把 NN 优于 MWPM 的原因之一归结为能更好处理相关 syndrome defect。([TU Delft Research Portal][3])

### 情况 D：严格实时闭环

即使某个离线 decoder 逻辑错误率略好，如果延迟无法进入快回路，也不能用于实时反馈。你的方案快回路只有矩阵乘加，硬件路径清晰。

---

## 7. 理论上什么时候你不一定赢？

你的方法不一定赢的场景是：

1. **噪声平稳且模型已知**
   fixed optimal linear decoder 或 oracle weighted MWPM 已经很好。

2. **错误模型完全匹配 MWPM 假设**
   独立图状错误 + 正确边权时，MWPM 很强。

3. **GKP modulo 边界样本很多**
   单一 (K s+b) 不能表达多分支后验，MMSE / closest-lattice / mixture-of-affine 可能更强。

4. **CNN 预测 (K,b) 的更新周期太慢**
   噪声变化快于慢回路更新，参数 stale 会伤害性能。

所以你的结论应该写成：

> 本方法不是要在所有噪声模型下替代 MWPM，而是在复杂、非平稳、带 analog GKP syndrome 的场景中，以 FPGA 友好的方式逼近自适应软信息解码。

---

## 8. 最推荐的论文实验叙事

你可以按这个顺序讲：

1. **先证明 GKP 内层有效**
   CNN-(K,b) 比 fixed (K,b)、nearest-integer、static LMMSE 更低 residual displacement / logical error。

2. **再证明自适应有效**
   在漂移、空间非均匀、burst、相关噪声下，CNN-(K,b) 接近 oracle (K^*,b^*)。

3. **再接外层码比较 MWPM**
   对比 hard MWPM、static weighted MWPM、adaptive weighted MWPM。

4. **最后展示硬件优势**
   FPGA 定点实现的延迟、吞吐、资源、位宽损失。

这样你的 claim 会非常稳：

> 相比 MWPM，本方法的优势不只是逻辑错误率，而是在复杂噪声下通过慢回路学习软信息参数，同时把快回路压缩为 FPGA 友好的仿射运算。
