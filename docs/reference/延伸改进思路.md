你的设计**是合理的**，而且从工程角度比“把完整 CNN/混合模型塞进 FPGA 快回路”更自然。它可以被表述为：

> **慢回路 CNN 做噪声场景识别和参数漂移预测；快回路 FPGA 只执行确定延迟的仿射 GKP 线性估计。**

也就是：

[
(K_t,b_t)=g_\phi(X_{t-L:t}),
\qquad
\hat e_t = K_t s_t+b_t,
]

其中 (X_{t-L:t}) 是一段 syndrome history、硬件监测量、校准特征或噪声场图；(s_t) 是当前 GKP syndrome；(\hat e_t) 是位移误差估计；FPGA 施加 (-\hat e_t) 或更新 displacement / Pauli frame。

## 1. 你的方案的理论定位：自适应 LMMSE / amortized linear decoder

在局部高斯近似下，GKP syndrome 和真实位移误差满足近似联合高斯模型。固定噪声参数 (\theta) 时，最优线性估计器是：

[
K^*(\theta)=\Sigma_{es}(\theta)\Sigma_{ss}(\theta)^{-1},
\qquad
b^*(\theta)=\mu_e(\theta)-K^*(\theta)\mu_s(\theta).
]

\hat e=K(\theta)s+b(\theta),\qquad K^*(\theta)=\Sigma_{es}(\theta)\Sigma_{ss}(\theta)^{-1}

所以你的 CNN 本质上是在学习：

[
X_{t-L:t}\mapsto \theta_t\mapsto K^*(\theta_t),b^*(\theta_t).
]

这不是“黑盒替代 GKP 解码”，而是**用神经网络在线逼近当前噪声条件下的最佳线性 GKP 估计器**。这和 GKP oscillator-to-oscillator 文献中的 linear estimation / MMSE estimation 是一致的：Wu、Brady、Zhuang 推导了 GKP-stabilizer code 的 MMSE 估计器，并明确指出 MMSE 优于 linear estimator；其线性估计器可看成只保留一个局部高斯分支的近似。([Quantum][1])

## 2. 为什么慢 CNN + 快 FPGA 很合理？

量子纠错解码有两个很不同的时间尺度：

**快时间尺度**：每一轮 syndrome 到来后必须低延迟处理。实时 QEC 文献反复强调，吞吐量和闭环延迟是关键指标；已有 FPGA-based NN surface-code decoder 的实验报告给出了 550 ns 确定闭环延迟，其中 NN 解码为 124 ns，用于 1.25 μs QEC cycle 内的反馈。([arXiv][2])

**慢时间尺度**：噪声场、GKP squeezing、测量偏置、ancilla 质量、loss、串扰、温漂通常不会每个 cycle 大幅随机变化，而是缓慢漂移或分段变化。因此让 CNN 在慢回路中估计 (K,b)，再让 FPGA 在快回路中执行矩阵乘加，是非常合理的两时间尺度分解。

这也和 GKP 文献中的“实时软信息”思想吻合。Noh、Chamberland、Brandão 的 surface-GKP 方案中，matching graph 的边权会根据 GKP analog information 和 syndrome 历史动态计算；他们指出这种动态利用 syndrome 历史是低逻辑失败率的重要来源。([arXiv][3]) 2025 年 QLDPC-GKP circuit-level soft-information 工作也比较了无软信息、预计算可靠度、实时软信息三种情况，结论是只有实时软信息场景带来显著 frame error rate 改善。([arXiv][4])

你的方案可以看成：**把“实时软信息”进一步压缩成 FPGA 友好的 (K,b)**。

## 3. 混合仿射解码会不会不方便 FPGA？

是的，**完整混合仿射解码通常更不方便 FPGA 部署**，尤其如果它需要实时计算多个分支权重：

[
\hat e
======

\sum_{m=1}^{M}
\pi_m(s,X)
\left(K_m s+b_m\right).
]

它比单一 (K s+b) 多了三类开销：

1. 多组矩阵乘法：(M) 个 (K_m s)；
2. 分支权重计算：(\pi_m(s,X))，可能涉及 softmax、指数、归一化；
3. 分支选择或加权平均：增加 DSP、BRAM、routing 和定点误差管理成本。

但它**不是完全不可部署**。可以有三个折中版本：

| 方案                    | FPGA 复杂度 | 表达能力 | 适合场景                      |
| --------------------- | -------: | ---: | ------------------------- |
| 单一 (K,b)              |       最低 |   中等 | 小噪声、单一分支占优、强实时约束          |
| 分段仿射 LUT              |      低到中 |   较高 | syndrome 边界附近错误重要         |
| Top-2 / Top-4 mixture |      中到高 |    高 | modulo 分支竞争明显             |
| 完整 mixture + softmax  |        高 |   最高 | 更适合 GPU/CPU 或离线 benchmark |

对 FPGA 来说，我不建议一开始采用完整 mixture。更好的路径是：**保留你的单一 (K,b) 快回路，把 mixture-of-affine 作为离线 upper baseline 或后续增强版本**。如果发现性能瓶颈主要来自 GKP modulo 边界附近，再考虑加入少量分支，例如 Top-2 分段仿射，而不是直接上完整 mixture。

## 4. 当前设计是否合理？结论：合理，但适用条件要讲清楚

你的方法合理的条件是：

第一，噪声漂移相对慢。CNN 的更新周期必须快于噪声统计量明显变化的时间尺度。若 (K,b) 更新延迟太大，快回路会使用过期参数。

第二，真实后验在大多数时候接近单分支高斯。也就是说 syndrome 多数时候不在 GKP modulo 判决边界附近。若大量样本落在边界附近，单一 (K,b) 会把多峰后验“平均掉”，这时 mixture 或最近格点/MMSE 会更优。

第三，CNN 输入确实包含足够信息来识别噪声场。输入只用当前 (s_t) 可能不够；最好用 syndrome history、局部空间 patch、测量幅度、GKP ancilla 指标、校准结果、温漂/损耗 proxy 等。

第四，FPGA 定点量化不会破坏 (K,b) 的稳定性。你需要单独评估 8/10/12/16-bit 定点下的 logical failure rate，而不能只看浮点仿真。

在这些条件下，你的架构很有优势：**它保留了 GKP 线性估计的物理结构，同时引入了对非平稳复杂噪声的自适应能力**。

## 5. 与其它解码方法相比，理论上能不能更优秀？

要分清“比谁优秀”。

### 能超过的对象

你的方法理论上很可能超过：

1. **固定 (K_0,b_0) 线性解码器**
   因为固定参数只适合 nominal noise；噪声漂移后，最优 (K^*,b^*) 改变，而 CNN 可以跟踪。

2. **closest-integer / hard GKP decoder**
   这种方法只利用 syndrome 的最近格点信息，不充分利用连续可靠度。GKP 和 GKP-concatenated 文献已经反复显示 analog / soft information 能显著提升性能。Raveendran 等人在 QLDPC-GKP 中展示，内层 GKP analog information 能提升外层 iterative decoder 阈值并降低 error floor。([Quantum][5])

3. **假设错误噪声模型的 MWPM / min-sum / BP**
   如果真实噪声存在空间相关、时间相关、偏置、非平稳漂移，固定边权或固定信道模型的 decoder 会失配。神经网络 decoder 在 surface-code 实验数据中能优于 MWPM，部分原因就是更好处理相关 syndrome 缺陷；Varbanov 等报告 NN decoder 在 Google Quantum AI 实验数据上 logical error rate 约比 MWPM 低 25%，并且使用 analog soft information 还能进一步降低逻辑错误率。([TU Delft Research Portal][6])

### 通常不能超过的对象

你的方法通常不能超过：

1. **已知真实噪声模型下的 oracle MMSE / ML decoder**
   如果对方知道完整真实后验 (p(e|s,\theta))，并且不受实时硬件限制，那它是 Bayes-optimal 或接近 Bayes-optimal。你的 (K,b) 是低复杂度近似。

2. **小规模精确 lattice theta / CVP / closest-point decoder**
   对小系统、离线仿真、可承受高复杂度时，精确或高精度近似的 GKP maximum-likelihood decoder 通常是更强 baseline。GKP lattice perspective 文献指出，GKP 最大似然解码可以用 lattice theta function 描述。([Quantum][7])

3. **完整 MMSE GKP decoder**
   Wu、Brady、Zhuang 的数值结果显示，MMSE 的 break-even point 可优于 square-lattice linear estimation；他们报告 single-layer codes using MMSE 的 break-even point 约为 (\sigma^*_{\rm MMSE}\approx0.605(5))，而 square lattice linear estimation 约为 (\sigma^*_{\rm lin}\approx0.558)。([Quantum][1])

所以最准确的说法是：

> 你的方法理论上可以优于固定模型、硬判决、静态线性和失配的传统 decoder；但不应声称能超过已知真实信道的 oracle MMSE / ML。它的核心优势是 **性能-延迟-可部署性折中**。

## 6. 一个有用的理论判据：预测 (K,b) 的误差如何影响性能

把偏置并入增广 syndrome：

[
\bar s=
\begin{bmatrix}
s\
1
\end{bmatrix},
\qquad
W=
\begin{bmatrix}
K & b
\end{bmatrix}.
]

则

[
\hat e = W\bar s.
]

对固定噪声条件 (\theta)，最优线性解码器是 (W^*(\theta))。如果你的 CNN 输出 (\hat W)，则在线性高斯假设下，额外 MSE 近似为：

[
\Delta{\rm MSE}
===============

{\rm Tr}
\left[
(\hat W-W^*)
,
\mathbb E[\bar s\bar s^T]
,
(\hat W-W^*)^T
\right].
]

\Delta\mathrm{MSE}=\mathrm{Tr}!\left[(\hat W-W^*),\mathbb E[\bar s\bar s^T],(\hat W-W^*)^T\right]

这给了你一个很清楚的理论目标：CNN 不一定要完美识别噪声参数 (\theta)，它只需要让 (\hat W) 比固定 (W_0) 更接近当前 (W^*(\theta))。如果做到这一点，你就能严格地降低线性估计族内的 MSE。

## 7. baseline 应该怎么设置？

我建议把 baseline 分成四层，否则审稿或答辩时容易被质疑“不公平”。

### A. GKP 内层解码 baseline

| Baseline                                        | 目的                       |
| ----------------------------------------------- | ------------------------ |
| No correction / no adaptive correction          | sanity check             |
| Closest-integer GKP decoder                     | 最基础硬判决                   |
| Static analytic linear decoder (K_0,b_0)        | 证明 adaptive 有用           |
| Static trained linear decoder                   | 排除“只是训练更好”的因素            |
| Oracle linear decoder (K^*(\theta),b^*(\theta)) | 线性族上界                    |
| Bayesian / MMSE decoder，小规模可算                   | 近似理论上界                   |
| Nearest-lattice / closest-point decoder         | GKP lattice 解码强 baseline |

其中 **oracle linear decoder** 很关键。它回答的问题是：你的 CNN 是否真的学到了接近当前最优线性解码器的参数。如果你的 CNN 和 oracle linear 差距很小，就说明慢回路预测是成功的。

### B. 自适应方法 baseline

| Baseline                                  | 目的                 |
| ----------------------------------------- | ------------------ |
| 滑动窗口估计协方差 + LMMSE                         | 传统统计自适应            |
| Kalman / recursive least squares 更新 (K,b) | 对比 CNN 是否必要        |
| 噪声参数分桶 + LUT (K,b)                        | 对比 CNN 是否优于查表      |
| MLP 输出 (K,b)                              | 证明 CNN 的空间局部归纳偏置有用 |
| CNN 直接输出 (\hat e)                         | 对比“物理结构约束”是否有优势    |
| CNN 输出 (\Delta K,\Delta b) vs 直接输出 (K,b)  | 验证残差学习稳定性          |

我特别建议加入：

[
K=K_0+\Delta K_\phi(X),\qquad b=b_0+\Delta b_\phi(X)
]

这个版本。它通常比直接预测完整 (K,b) 更稳，也更容易解释。

### C. 外层码 baseline，如果你有 surface-GKP / QLDPC-GKP

| Baseline                                               | 目的                    |
| ------------------------------------------------------ | --------------------- |
| hard MWPM / hard min-sum                               | 不用 analog information |
| soft MWPM / soft min-sum，静态边权                          | 使用固定 soft info        |
| dynamic soft MWPM / real-time soft info                | 当前强 baseline          |
| 你的 CNN-(K,b)+FPGA linear inner decoder + outer decoder | 完整方案                  |
| oracle soft-information outer decoder                  | 上界                    |

surface-GKP 文献中，MWPM、动态边权、analog information 都是自然 baseline。Wang 等的 surface-GKP CNN decoder 报告在连续变量系统下使用卷积神经网络解码，并给出比 MWPM 更高的阈值结果，可作为 NN 类 baseline 参考。([Nature][8])

### D. 硬件 baseline

| 指标                      | 必须比较                     |
| ----------------------- | ------------------------ |
| latency                 | CNN 慢回路延迟 + FPGA 快回路闭环延迟 |
| throughput              | 每秒 syndrome 轮数           |
| FPGA LUT/FF/DSP/BRAM    | 资源占用                     |
| 定点位宽                    | 8/10/12/16-bit 性能曲线      |
| 功耗                      | 如果面向硬件论文，最好报告            |
| 参数更新带宽                  | 慢回路传输 (K,b) 到 FPGA 的开销   |
| stale parameter penalty | (K,b) 延迟更新造成的性能损失        |

这层很重要，因为你的主张不是“最强离线 decoder”，而是“复杂噪声下高性能、低延迟、可部署 decoder”。

## 8. 实验场景应该怎么设计？

至少需要这几类噪声场景：

1. **stationary Gaussian displacement**
   证明你的方法不会比标准 LMMSE 差太多。

2. **缓慢漂移噪声**
   例如 squeezing、loss、measurement variance 随时间漂移。这里你的方法应该明显优于 fixed (K,b)。

3. **空间非均匀噪声场**
   某些 mode 或 lattice patch 噪声更强。CNN 的局部卷积结构应该有优势。

4. **时间相关噪声**
   例如 (1/f) noise、burst noise、Markov switching noise。测试慢回路能否跟踪。

5. **模型失配噪声**
   训练在 Gaussian + drift，测试在轻微非高斯尾部、偏置、相关噪声。证明泛化。

6. **GKP modulo 边界压力测试**
   专门统计 syndrome 接近 (\pm\sqrt{\pi}/2) 的样本性能。这能判断是否需要 mixture-of-affine。

## 9. 如何判断是否需要混合仿射？

你可以做一个很直接的 ablation：

1. 当前单一 (K,b)：
   [
   \hat e=Ks+b.
   ]

2. Top-2 piecewise affine：
   [
   \hat e =
   \begin{cases}
   K_1s+b_1,& s\in \mathcal R_1,\
   K_2s+b_2,& s\in \mathcal R_2.
   \end{cases}
   ]

3. 离线完整 mixture-of-affine：
   [
   \hat e=\sum_m \pi_m(K_ms+b_m).
   ]

如果 2 或 3 只在极少数边界样本上提升，而总体 logical error rate 改善很小，就不要牺牲 FPGA 简洁性。如果 mixture 在目标噪声区间显著降低 logical failure rate，才考虑硬件化一个简化版，比如 LUT 分支选择 + 两组 (K,b)。

我的建议是：**先不要换掉你现在的架构。把 mixture 作为离线 upper bound，确认性能瓶颈后再决定是否硬件化。**

## 10. 最推荐的论文表述方式

你可以把方法命名为类似：

**Two-timescale CNN-adaptive affine decoder for approximate GKP codes**

核心卖点可以写成三点：

1. **Physics-structured**：快回路不是黑盒，而是 GKP syndrome-informed affine displacement；
2. **Noise-adaptive**：慢回路 CNN 根据复杂噪声场预测 (K,b) 的漂移；
3. **Hardware-friendly**：实时路径只包含定点矩阵乘加，适合 FPGA 低延迟实现。

理论上，它的定位不是取代 MMSE/ML，而是：

> 在受限硬件延迟下，逼近当前噪声条件的 oracle linear GKP decoder，并在非平稳、相关、模型失配噪声下优于静态线性和硬判决 baseline。

这是一条很清晰、也比较容易被接受的论证路线。

是否可以拿这套CNN+FPGA方法去和MWPM方法或者其它解码方法进行比较？

可以，而且**应该比较**。但要注意：你的 CNN+FPGA 方法和 MWPM 不一定处在同一层级。最公平的做法是把比较分成两类：

1. **算法性能比较**：逻辑错误率、阈值、残余位移方差、frame error rate。
2. **系统实现比较**：延迟、吞吐、FPGA 资源、定点量化损失、参数更新带宽。

否则容易出现“不公平比较”：例如拿你的实时 FPGA 快回路去比离线 MWPM 的逻辑错误率，或者拿你的自适应 CNN 去比静态 MWPM 的固定边权。

## 1. 可以和 MWPM 比，但要明确 MWPM 在哪一层

如果你只做 **单模或多模 GKP 内层位移估计**：

[
\hat e = K s+b,
]

那么 MWPM 不是最自然的直接 baseline。此时更合适的 baseline 是：

| 任务          | 合理 baseline                                 |
| ----------- | ------------------------------------------- |
| GKP 内层位移估计  | nearest-integer / closest-point GKP decoder |
| GKP 内层软信息   | fixed linear estimator, MMSE estimator      |
| 多模 GKP 格码   | nearest-lattice / closest-vector decoder    |
| 近似 GKP 有限能量 | static (K,b), oracle (K^*,b^*), MMSE        |

MWPM 更适合用于 **surface code、toric code、surface-GKP、GKP-surface concatenation** 这类外层拓扑码解码。surface-GKP 文献中确实常用 MWPM 作为基线；例如 Wang 等人在 surface-GKP 中先用 MWPM 解 3D 时空图，然后又引入卷积神经网络 decoder，并报告 CNN threshold 高于 MWPM baseline。([Nature][1])

所以如果你的系统是：

[
\text{GKP 内层} + \text{surface/toric/QLDPC 外层},
]

那就非常适合和 MWPM 或 BP / min-sum / union-find 比较。

## 2. 最公平的 MWPM baseline 应该有多个版本

不要只设置一个“MWPM baseline”。建议至少设置以下四个：

| Baseline                 | 说明                             | 目的                       |
| ------------------------ | ------------------------------ | ------------------------ |
| **Hard MWPM**            | 只用离散 syndrome，不用 GKP analog 信息 | 最基础传统 baseline           |
| **Static-weight MWPM**   | 边权由固定 nominal 噪声模型给出           | 对比静态噪声假设                 |
| **Adaptive-weight MWPM** | 边权根据当前估计噪声更新                   | 对比你的 CNN 自适应优势是否来自“更新权重” |
| **Oracle-weight MWPM**   | 使用真实噪声参数或真实错误概率生成边权            | MWPM 类方法的近似上界            |

你的方法如果只和 Hard MWPM 比，容易被质疑 baseline 太弱。GKP 相关文献已经显示 analog/soft information 对外层解码很重要：QLDPC-GKP 工作表明，内层 GKP analog information 可以提高外层 iterative decoder 阈值，并降低或消除 error floor；2025 年 circuit-level QLDPC-GKP 工作也强调，内层 bosonic syndrome 的 analog information 会用于 informing 外层 stabilizer code 解码。([Quantum][2])

因此，真正有说服力的比较应该是：

[
\text{CNN-adaptive } K,b
\quad \text{vs.} \quad
\text{soft/adaptive MWPM}.
]

## 3. 你的方法和 MWPM 比的核心卖点不是“万能更准”，而是“自适应 + 低延迟”

MWPM 的优势是成熟、可解释、在图状独立错误模型下非常强。你的 CNN+FPGA 方法的优势是：

[
\text{复杂噪声场} \Rightarrow \text{CNN 估计漂移}
\Rightarrow K_t,b_t
\Rightarrow \text{FPGA 低延迟仿射解码}.
]

也就是说，你的强项是：

* 噪声非平稳；
* 存在空间非均匀噪声；
* 存在时间漂移；
* 存在测量偏置；
* 存在相关错误或模型失配；
* 需要严格实时闭环；
* 不希望在快回路中跑复杂图匹配或完整神经网络。

这和近年的 NN decoder 结果方向一致。Varbanov 等人在 surface-code 实验数据上报告，NN decoder 可以比 MWPM 取得更低逻辑错误率，原因之一是 NN 更能处理导致多个相关 syndrome defect 的错误；他们还报告，在 Google Quantum AI 实验数据上 NN 逻辑错误率约比 MWPM 低 25%，加入 analog soft information 又可进一步降低逻辑错误率。([TU Delft Research Portal][3])

但你不应该声称“理论上一定优于 MWPM”。更准确的说法是：

> 在非平稳、相关、带 analog syndrome 的复杂噪声场中，CNN-adaptive affine decoder 有机会优于静态 MWPM 或失配 MWPM；但在 MWPM 拿到 oracle 边权、错误模型正好图状独立、且无实时硬件限制时，MWPM 仍然可能非常强。

## 4. 推荐的完整比较矩阵

我建议你的实验表格这样设计：

| 类别               | 方法                                    |    是否自适应 | 是否用 analog info | 是否硬件友好 |
| ---------------- | ------------------------------------- | -------: | --------------: | -----: |

| 固定线性             | fixed (K_0,b_0)                       |        否 |               是 |      是 |
| 统计自适应            | sliding-window LMMSE / RLS            |        是 |               是 |      中 |
| 你的方法             | CNN-predicted (K_t,b_t) + FPGA        |        是 |               是 |      是 |
| 外层传统             | hard MWPM                             |        否 |               否 |      中 |
| 外层 soft          | static weighted MWPM                  |        否 |               是 |      中 |

| 离线上界             | MMSE / ML / closest lattice           | 是，oracle |               是 |    通常否 |

最关键的 baseline 是这三个：

]

[
\text{adaptive weighted MWPM},
]

]

如果你的方法能接近 oracle (K^*,b^*)，并且在复杂漂移噪声下超过 fixed (K_0,b_0) 和 static weighted MWPM，那就说明你的慢回路 CNN 真的学到了噪声漂移。

## 5. 评价指标不要只看逻辑错误率

建议报告：

| 指标                                    | 为什么重要           |
| ------------------------------------- | --------------- |
| logical error rate / frame error rate | 主要纠错性能          |
| threshold 或 pseudo-threshold          | 展示可扩展趋势         |
| residual displacement variance        | 直接衡量 GKP 内层解码质量 |
| latency                               | 你的 FPGA 快回路核心优势 |
| throughput                            | 是否满足 QEC cycle  |
| FPGA LUT / FF / DSP / BRAM            | 可部署性            |
| 定点位宽敏感性                               | 证明不是浮点幻觉        |
| stale-(K,b) penalty                   | 慢回路更新延迟的影响      |
| train/test noise mismatch             | 证明泛化能力          |
| burst / drift / correlated noise 下性能  | 证明 CNN 的必要性     |

这点很重要，因为你的方法可能不是所有条件下逻辑错误率最高，但它可能在 **性能-延迟-资源** 三维折中上最好。实时 QEC 硬件论文已经把这种系统指标作为核心；例如 2026 年 FPGA-based NN surface-code 实验报告了 550 ns 确定闭环延迟，其中 NN 解码 124 ns，并能在 1.25 μs QEC cycle 内反馈。([arXiv][4])

## 6. 理论上什么时候你会赢？

你的 CNN+FPGA 方法最可能赢的场景是：

### 情况 A：噪声参数慢漂移

固定 MWPM 或 fixed (K,b) 使用过期信道模型。你的 CNN 根据 syndrome history 更新：

[
K_t,b_t.
]

这时你可以接近当前条件下的 oracle linear decoder。

### 情况 B：空间非均匀噪声

某些区域 squeezing 较差、loss 较大、测量偏置较强。CNN 可以从局部 syndrome pattern 中识别噪声热点，输出局部修正矩阵或局部 (K,b)。静态 MWPM 若仍用均匀边权，会吃亏。

### 情况 C：相关错误或非图状错误

MWPM 最适合图状匹配问题；如果错误导致多个相关 syndrome defects，NN 类方法可能更容易学习这些相关结构。surface-code NN decoder 文献中就把 NN 优于 MWPM 的原因之一归结为能更好处理相关 syndrome defect。([TU Delft Research Portal][3])

### 情况 D：严格实时闭环

即使某个离线 decoder 逻辑错误率略好，如果延迟无法进入快回路，也不能用于实时反馈。你的方案快回路只有矩阵乘加，硬件路径清晰。

## 7. 理论上什么时候你不一定赢？

你的方法不一定赢的场景是：

1. **噪声平稳且模型已知**
   fixed optimal linear decoder 或 oracle weighted MWPM 已经很好。

2. **错误模型完全匹配 MWPM 假设**
   独立图状错误 + 正确边权时，MWPM 很强。

3. **GKP modulo 边界样本很多**
   单一 (K s+b) 不能表达多分支后验，MMSE / closest-lattice / mixture-of-affine 可能更强。

4. **CNN 预测 (K,b) 的更新周期太慢**
   噪声变化快于慢回路更新，参数 stale 会伤害性能。

所以你的结论应该写成：

> 本方法不是要在所有噪声模型下替代 MWPM，而是在复杂、非平稳、带 analog GKP syndrome 的场景中，以 FPGA 友好的方式逼近自适应软信息解码。

## 8. 最推荐的论文实验叙事

你可以按这个顺序讲：

1. **先证明 GKP 内层有效**
   CNN-(K,b) 比 fixed (K,b)、nearest-integer、static LMMSE 更低 residual displacement / logical error。

2. **再证明自适应有效**
   在漂移、空间非均匀、burst、相关噪声下，CNN-(K,b) 接近 oracle (K^*,b^*)。

3. **再接外层码比较 MWPM**
   对比 hard MWPM、static weighted MWPM、adaptive weighted MWPM。

4. **最后展示硬件优势**
   FPGA 定点实现的延迟、吞吐、资源、位宽损失。

这样你的 claim 会非常稳：

> 相比 MWPM，本方法的优势不只是逻辑错误率，而是在复杂噪声下通过慢回路学习软信息参数，同时把快回路压缩为 FPGA 友好的仿射运算。
