# T41: Milestone 2K 论文组装门审查 —— 给人类的说明

## 1. Milestone 2K 现在证明了什么

Milestone 2K（由 T34 + T35 组成）证明的是：**论文组装所需的"工具箱"已就位。**

具体来说：

- **T34** 建立了一份完整的"主张-证据对照表"（claim/evidence ledger）。它把仓库里当前能安全写入论文的所有主张（C1–C11）、所有计划中的图表（F1–F3, T1–T5）逐条列出来，标注了每条主张的支撑证据路径和边界限制。
- **T35** 建立了论文骨架（含标题候选、摘要/引言/方法/实验/结果/局限/结论的结构大纲）和审稿人风险审计（列出了审稿人可能提出的 20 类质疑点、6 个过度表述陷阱，以及"不能写成什么样"的清单）。

这两个产物的核心价值是：**后续写论文时不需要再从零判断"这个结论能不能写"——对照表已经写好了。**

## 2. 它仍然不能证明什么

Milestone 2K **不改变任何实验证据等级**。以下事实与 Milestone 2K 之前完全相同：

- 当前 benchmark 仍然是 **mock-backed 软件 HIL**，不是真板验证。
- `.tflite` 真实运行时在当前机器上**仍不可用**。
- 训练链只完成了**一次 CPU-only smoke**，不等于完整复现性或跨平台可移植性。
- 机制诊断只支持**单个 seed**，不是因果证明。
- `statcalib` 只是**接口级合约**，不是已集成的校准比较器。
- 论文正文**尚未开始撰写**。

## 3. 为什么下一步是门审查而不是直接开始写论文或继续部署工作

三个原因：

1. **论文定位需要一次性决策。** T35 的审稿人风险审计指出，当前骨架中缺少 Background / Related Work 章节，且标题候选偏保守。在开始写正文之前，需要先决定论文的整体定位（偏方法论文还是偏工程系统论文？标题怎么取？），并在骨架中补齐 Background / Related Work。这些是"方向决策"，不是"边写边调"的事。

2. **部署和硬件路径仍有硬阻塞。** T32（`.tflite` runtime）被当前机器缺少 `tensorflow` 阻塞；T37（真板 smoke）被硬件/权限/bitstream 前提阻塞。在阻塞条件解除之前，继续推部署工作只会产出更多"计划"而不是"证据"。

3. **门审查是项目治理的必经步骤。** 按项目治理规范，每个 milestone 结束后必须做一次只读审查，确认当前证据没有被静默升级、主张没有被过度外推，然后再决定下一步。T41 就是这个审查节点。

**审查结论**：Milestone 2K 允许关闭（`Allow`）。下一步建议是补一个 Background / Related Work 骨架任务（T42），补完后再逐章节推进正文撰写。
