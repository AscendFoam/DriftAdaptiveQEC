**口头汇报稿**

老师好，我这次汇报的是 CNN-FPGA-GKP 量子纠错项目的阶段性进展。这个项目的核心目标，是在 GKP 量子纠错场景下，把“实时、稳定的 FPGA 快回路”和“能够跟踪漂移的慢回路自适应更新”结合起来，形成一条可部署的闭环解码链路。这里可以先简单解释几个词。GKP 可以理解为一种连续变量量子纠错编码；LER 是逻辑错误率，数值越低越好；baseline 就是对照方法，也就是我们拿来比较的基线；HIL 是 hardware-in-the-loop，意思是把运行时链路、时序、量化和接口都纳入闭环验证，而不是只做离线训练。

整个项目为什么要分 P0 到 P4，而不是一开始就直接上板或者直接拼最终结果？原因是这个问题同时包含物理建模问题、模型训练问题、工程一致性问题和正式对比问题。如果这些问题混在一起，最后即使得到一个数字，也很难解释这个数字到底说明了什么。所以我们是按“先证明问题存在，再证明模型可学，再证明工程链路成立，最后再给正式排序”的方式推进。

先说 P0。P0 的任务不是做 CNN，而是先证明这个课题值得做。这里我们用物理仿真去看：如果噪声参数发生漂移，固定参数解码器会不会失配。我们测试了几类典型漂移场景。比如 linear_low 表示低强度线性漂移，也就是参数缓慢持续偏移；step_mid 表示中等幅度突变；sinusoidal 表示周期漂移，类似温漂或振动导致的周期变化；random_walk 表示随机游走，也就是每一步只漂一点，但长期会积累。结果显示，在这些场景下，固定参数口径和理想可调口径之间有明显差距，例如 linear_low 是 0.4237 对 0.0205，step_mid 是 0.42665 对 0.01855，sinusoidal 是 0.42530 对 0.02405，random_walk 是 0.41200 对 0.01565。这说明漂移确实会显著推高逻辑错误率，问题是真实存在的，项目有明确物理动机。但这一阶段只能说明“需要自适应”，还不能说明“CNN 一定有效”。

接下来是 P1。P1 的任务是先回答一个问题：慢回路里到底有没有可学习信号。如果没有，那么后面不管是 FPGA 还是 HIL，都是在没有意义的前提上往前堆。我们在这个阶段构建了数据集，用窗口统计特征去预测噪声相关参数，训练了一个轻量级的 TinyCNN。这个模型结构比较简单，可以概括为一层卷积、ReLU 激活、2x2 平均池化、再接两层全连接层，也就是 Conv-ReLU-Pool-FC-FC。这样设计不是为了追求特别深的网络，而是为了后续量化和部署更容易。P1 的结果是：float 模型 MSE 为 0.293336，MAE 为 0.220503，R2_mean 为 0.994352；int8 量化模型的 MSE 为 0.297742，MAE 为 0.221944，R2_mean 为 0.994212。这里 MSE 和 MAE 可以理解为预测误差，越低越好；R2 可以理解为拟合程度，越接近 1 越好。这个结果说明两件事。第一，窗口统计里确实有可学习信号，模型不是拍脑袋硬加进去的。第二，int8 量化后性能下降很小，说明模型具备进一步走向部署的可能性。但要强调，P1 还是 offline，也就是脱离运行时闭环的训练验证，它不能直接外推到真实闭环里一定更好。

P2 是一个非常关键的阶段。P2 要解决的不是“模型能不能学”，而是“工程上会不会把好结果做没”。因为真实部署里，量化、寄存器、DMA、AXI、bank 切换、参数写回时序，这些问题往往比模型本身更容易出问题。这里也顺便解释几个词。DMA 是板级数据搬运通道；AXI 可以理解为 FPGA 和外部逻辑之间常见的寄存器和总线接口；bank 指参数双缓冲区，也就是 A/B 两套参数区，一套正在被快回路使用，另一套由慢回路写入；commit 不是提交代码，而是在安全时刻把 staging bank 切换成 active bank；overflow 指缓冲区超限或数据拥堵告警。P2 中我们把 fixed_baseline、oracle_delayed、model_artifact、int8_artifact 放到统一的硬件行为级口径下比较。fixed_baseline 是固定参数方案；oracle_delayed 可以理解为“带延迟的理想上界”，也就是使用延迟后的真实目标参数做参照；model_artifact 是直接调用训练好的浮点模型产物；int8_artifact 是调用量化模型产物。结果显示，linear_med 场景下 model_artifact 的 LER 是 0.696206，而 fixed 是 0.816067；step_large 是 0.731906 对 0.937822；sinusoidal_mid 是 0.759289 对 1.019033。同时，commit_count_mean 等于 7.0，说明慢回路确实在持续提交新参数；快慢回路冲突率为 0，说明双 bank 和 commit 的同步机制是有效的。这里可以说，P2 是项目从“论文上看起来可行”走向“工程上也站得住”的分水岭。

P3 进一步回答的是：真实运行时闭环是否打通。也就是说，行为级仿真还不够，我们还要把真实部署产物、推理服务模式、提交时序这些都纳入软件 HIL。这里再解释几个词。真实 .tflite 产物，就是模型正式导出的部署文件；subprocess 指把推理放到独立进程里运行，用来模拟未来 ARM 侧或部署侧服务与主程序解耦，而不是所有逻辑都塞在一个 Python 进程里；mock HIL 是“软件闭环模拟板级接口”的验证方式，不是真板，但比单纯离线更接近真实运行时。P3 里我们比较了 fixed_baseline_mock、float_artifact_mock 和 int8_artifact_mock。结果分别是 1.1987018、1.1405753 和 1.1407845，float 和 int8 的 mock LER gap 只有 2.09e-04。这个结果说明，量化模型和浮点模型在软件 HIL 闭环中几乎保持了一致的行为，运行时语义没有被明显改坏。所以 P3 可以支持这样一个结论：软件侧的 HIL 链路已经打通，真实部署产物也具备进入正式 benchmark 的资格。但这里必须明确，P3 软件 HIL 完成，不等于 P3 真板 HIL 完成。真板联调仍然是后续可扩展工作，而不是当前已经完成的结论。

最后是 P4。P4 的任务是把前面各阶段积累的能力，放到统一 benchmark 中给出正式排序。这里“冻结 scenario、seed 与统计口径”很关键，意思是把测试场景、随机种子和统计方法全部固定，避免通过更换场景、挑选随机性或者改变统计方式来人为优化结果。在正式 benchmark 中，我们统一比较了 EKF、UKF、RLS Residual-B、Constant Residual-Mu 和 Hybrid Residual-B 等方法。EKF 和 UKF 都是经典状态估计方法，UKF 可以理解为对非线性更友好的版本；RLS Residual-B 是经典递推残差修正；Constant Residual-Mu 是固定常数修正；Hybrid Residual-B 是当前正式主线，也就是“稳定 classical teacher 打底，再由 CNN 做轻量 residual 修正”。正式结果是：Hybrid Residual-B = 0.798332，UKF = 0.817974，Constant Residual-Mu = 0.825719，RLS Residual-B = 0.827908，EKF = 0.828369。也就是说，当前最强正式结果是 Hybrid Residual-B，而最强经典 baseline 是 UKF。这说明在统一 benchmark 下，我们已经有了一个相对稳定的正式主线。

接下来我想强调这次项目最重要的机制认识。我们曾经观察到一个现象，就是去掉 teacher params，也就是 No TeacherParams，在离线训练里会更好。但在 formal HIL，也就是把时序、量化、commit 和 benchmark 全部固定后的正式闭环里，这个优势会翻转。换句话说，离线训练改善，不等于 formal HIL 改善。这个结论非常重要。它说明模型在静态数据上学得更好，不代表放进双回路闭环后一定更好。当前更合理的解释，不是“teacher params 本身坏掉了”，而是“teacher params 的表示方式可能存在低方差、高冗余、与其他通道耦合不佳的问题”。所以后续工作的重点，不应该继续纠结“要不要删掉 teacher params”，而应该转向“teacher params 怎样编码更合适”。

最后说一下当前系统的整体工作方式。快回路运行在 FPGA 侧，每 5 微秒读取当前 active bank 中的参数 K 和 b，完成一次确定性线性解码。K 可以理解为解码增益或线性变换矩阵，b 可以理解为偏置修正项。快回路不会等慢回路。慢回路则在更长的时间尺度上累积 syndrome 的直方图窗口，先通过 classical teacher 给出一个稳定的参数建议，再由轻量 CNN 学一个小的 residual 修正，最后经由 ParamMapper 映射成快回路真正使用的 K 和 b。新参数不会直接覆盖旧参数，而是先写入 shadow bank，再在安全边界 commit 切换。这样做的核心目的，是保证快回路的实时性和稳定性不被慢回路打断。

总结一下，目前可以稳定对外汇报的三条结论是：第一，这个课题本身是值得做的，因为漂移确实会让固定参数解码失配。第二，当前最稳的正式主线是 Hybrid Residual-B，最强经典 baseline 是 UKF。第三，已经明确观察到 offline 不等于 formal HIL，这不是坏消息，而是一个很有论文价值的机制结论。下一步更值得做的工作，是围绕 teacher params 的编码方式做更聚焦的表示消融实验，用 benchmark-only 的口径验证编码改动能不能把离线优势真正转成 formal HIL 收益，而不是继续把大量算力投在 No TeacherParams 的全量长跑上。

如果老师后面想追问，我建议我可以继续从三个方向展开：第一，噪声场景为什么这样设计；第二，为什么双回路比单回路更符合实时部署；第三，为什么当前论文主问题不适合把 MWPM 作为 P4 启动前的主 baseline。
