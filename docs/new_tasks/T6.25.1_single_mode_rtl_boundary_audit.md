## 深审发现与修正

首轮按旧文档可把 T6.2.1、T6.7.3、T6.9.1 理解成同一系统的互补证据。逐模块展开后发现这是不成立的：

- `gkp_fast_path_production_top` 实例化 core，拥有 CRC32、完整 image staging、version CAS、cancel/drain/snapshot，但没有 Route-A policy/LKG；
- `route_a_integrated_qualification_top` 直接实例化 core+policy，并将 raw `cfg_we`、`bank0_trusted`、`bank1_trusted` 暴露为外部输入，没有实例化 production management；
- T6.2.2 的 long-run wrapper同样直接实例化 core；
- T6.9.1 的 synthesis harness 包裹 `route_a_integrated_qualification_top`，所以三种子 P&R 也不是 production-management+policy 的同一 top。

因此没有复制旧 PASS。任务板已把 T6.25.2 收紧为先构建唯一 converged production top；后续 property、百万周期和三种子 P&R 必须针对完全相同的 top。初版审计还将 child name 当 token 搜索，可能被注释误触发；最终改为 module-instantiation 语法检查，并加入 RTL 正文禁词扫描、capability-gap独立重算和 20 个 targeted semantic mutations。
