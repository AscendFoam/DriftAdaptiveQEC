## 执行方案与实际完成内容

1. 继承并实时验证 T6.8.6 的 8 个旧外部实现，不复制旧摘要后脱离父工件；另从 8 个新一手来源提取 10 个具体 implementation rows。
2. 新增行覆盖 Micro Blossom、GNN accelerator（average/max 两种边界）、Rethink TCN、BP+OSD（surface/bicycle 两个问题）、DECONET、CED、GARI-24 与 GARI-3；其中 5 行带 Direct-NN/learned implementation 描述。
3. 每行分别登记 code family、distance/problem size/window、input/output、device、precision、clock、latency boundary/statistic、cycles、II、LUT/FF/BRAM/DSP/power、evidence state 与不可比原因；未知值保持 null。
4. 对 18 个外部 implementation 逐行应用 exact task-signature eligibility。外部行均不是本项目的 single-mode square-GKP、10-bit folded syndrome 到 frame/event action 的同任务实现，因此 same-task external comparator=`0`，不产生 raw-ns 排名。
5. 六类候选没有被强行补成数值行：QASBA、QUEKUF、soft-syndrome qLDPC、diversity emulator、CED d=15 resource-only、GKP-specific FPGA negative search。相对 speedup、family summary、异问题尺寸资源或未找到的绝对 timing 均不反推为伪精确数字。
6. 明确保留证据边界：Rethink 正文 271 cycles 与表格 267 cycles 的冲突；CED 的 d=15 资源不填入 d=9 latency 行，1.2 W 仅为 24 个 EFE branch 的动态功耗；DECONET 的 mean latency 与 inverse throughput 不互换；GARI preliminary implementation 不升级为 QPU closed loop。
7. 深审发现 T6.8.6 项目行仍引用旧 LUT4=3357，而当前 T6.19.1 为 LUT4=3377。没有放宽 live verification：修正 source ledger、T6.8.6 adapter test 和 source audit expectation，重新生成 T6.8.6，并顺序重建 T6.16--T6.19 全部受影响的 exact-hash 证据链。

## 深度检查与非 demo 修正

- 没有按用户图片的“极快/高/低”类别印象填表；只提取能定位到问题尺寸、边界和 statistic 的一手数值。
- 没有把 surface-code/qLDPC 的纳秒数与 single-mode GKP 6-cycle path混排，也没有把 mean、p95/p99、worst、II、inverse throughput 与 source-to-action 互换。
- 没有把 HLS/synthesis/P&R、physical FPGA synthetic-input、真实 QPU closed-loop 合并成一个 evidence level。
- 没有因为尚未找到 GKP-specific FPGA comparator 就声称其不存在；结论限定为冻结检索协议下未识别到合格一手来源。
- 没有为制造 same-task comparator 编写近似外部 decoder、demo RTL 或推算缺失资源。
- stale LUT 锚点由联合测试真实检出；修复源头并重建所有下游 hash，而不是修改期望值或跳过 parent validation。
