### 2. 同权限与 action-conditioned pairing

- primary promotion 输入固定为 T9.2.7 同一 bit-accurate frontend 的 `FIXED_POINT_DERIVED_LLR`。
- raw/recorded IQ 与 binary syndrome 只作分别闭合的输入消融；禁止每个 architecture 选择自己最有利的输入。continuous/ideal simulator IQ 只可进入 privileged ceiling。
- common-random-number pairing 只共享六态初始条件、device/scenario draw 和外生 innovation/RNG manifest；策略执行 action 后，物理 transition 与 trace 必须按 policy 分叉并保存逐方法 hash，禁止用同一完整 trace 做 open-loop replay。
- action schema 统一为 trusted recovery codebook、bounded residual、phase frame、leakage/reset FSM 与 LKG fallback；frontend、codebook 和 execution-environment manifest 尚未由 T9.2.7/T9.3.4/T9.4.2 释放，因此当前任何 matched rank 都被阻断。

### 3. Compute、selection 与 failure 合同

- batch=1、256-cycle update cadence、1 pinned physical core、1 thread、online GPU=false。
- 1 ms online deadline 包含 IQ/LLR preprocessing、feature extraction、model inference、state update、serialization 和 host-to-bank transfer；timeout 只允许不更新，不能阻塞六周期 LKG fast path。
- envelope 为 131,072 parameters、1 MiB persistent state、16 MiB workspace、256 MiB peak RSS delta、262,144 MAC/update、1,048,576 FLOP/update。
- 每 family 最多 64 次 selection evaluation；learning 固定 16 configs × 4 restarts。每个 attempt 保存 family/candidate/restart/seed、hyperparameters、config/environment/sample/checkpoint hash、optimizer work、CPU/GPU hours、validation、failure、selected 与 selection reason。

### 4. Pilot、功效与统计推断

- pilot 固定 128 independent clusters：8 个 macro scenario × 16；只打开一次，只能晋升最多一个 proposed candidate，不能删除 mandatory baseline 或支持论文 claim。
- round-LER formal 以 18 个 fixed comparators、familywise alpha=0.05、power=0.90、baseline `p_L=0.08`、真实相对改善 15%、simultaneous relative LCB 超过 10%、paired absolute-difference SD ceiling=0.028 设计。
- 独立重算得到 required `N=806`；冻结 planned `N=808/backend=8×101`，近似设计功效 `0.9010994596`。
- final inference 使用 100,000 次、固定 seed 的 paired outer-cluster maxT bootstrap；六态、所有方法、round/window 及 reset/leakage/control/fallback/timeout 事件保留在同一 cluster。
- relative ratio 在每个 bootstrap replicate 内重算；baseline LER=0 时 relative contrast/CI 为 null，只保留 absolute contrast，禁止 epsilon。
- 90% 仅是 round-LER comparator screen 的设计功效，不是 lifetime 或全部 multi-endpoint family 的 joint-power 声明。六态 survival/lifetime 功效等待 T9.6.1 的 event-rate proxy，当前保持 typed null。

## 反简化实现复核

本任务不是只写一张方法表：

1. 功效不是沿用旧 60/800 数字；加入 UKF 与 CNN 后将 comparator divisor 从 16 改为 18，重新得到 806/808，并明确 lifetime power 尚未完成。
2. 配对样本不是强迫所有 policy 使用同一 post-action physical trace；改为共享外生随机数、保留 action-conditioned 分叉，避免把 closed-loop benchmark 偷换成 open-loop replay。
3. 文献去重不是把 GitHub/Zenodo 当论文版本，也不是只计算 dedup key；保存 raw-hit ledger、逐次 merge event、artifact 分栏和 conflicting-ID failure。
4. 旧 CNN/NMF/BOCD/SMC 的历史代码存在不等于 Phase-9 qualified；其输入、action、precision、budget、selection 和 lifetime 缺口逐项保留为 typed null。
5. generator 在最终 gate 形成前不得发布 PASS Markdown；失败 CLI 返回非零并写明不可用。Markdown、CSV 与实现均由 live hash 和独立测试复核。
6. 内建 mutation 不能在本来已失败的 baseline 上“假装杀死”；audit 先要求 36 个 baseline gates 全真，再逐门变异。
